## Устройство

Сервер написан на Node.js с использованием встроенного SQLite. Клиент использует HTML, CSS и JavaScript без сборщика. Рабочие изменения выполняются через API с проверкой сессии и прав; версии, журнал, квитанции команд и резервные копии обеспечивают согласованность и восстановление

Код расположен в `locus/`. Основные точки входа:

- `server.js`: вход, маршрутизация API, защищённая выдача страниц
- `api/`: предметные операции, проверки полей, прав и связей
- `db/`: схема, генераторы, миграции и индексы
- `public/`: экраны и общие компоненты интерфейса
- `design/`: канон интерфейса и контроль отклонений
- `ops/`: выпуск, резервирование и восстановление
- `tests/`: отдельные временные базы, серверы и искусственные участники

## Проверка

Нужны Node.js 22.13 или новее и Python 3. Внешних зависимостей у сервера и основного набора тестов нет

```sh
cd locus
npm test
```

Тесты создают собственные временные базы и процессы на случайных локальных портах. Искусственные пароли и ключи в тестах относятся только к этим стендам

Для генерации схемы и проверки интерфейса:

```sh
cd locus
python3 db/sborka_shemy.py
npm run test:design
```

Документ схемы находится рядом с каталогом `locus/`, поэтому структура этого репозитория важна для генератора

## Состав публичной редакции

Рабочая база, вложения, резервные копии, журналы, переписка, конфигурация доступов, фотографии команды и реальная клиентская информация сюда не включены. Прототипные предметные данные очищены; примеры принципов заменены синтетическими. Сообщения об ошибках адресованы роли администратора, а не конкретному человеку

Репозиторий имеет новую историю Git. Исторические личные учётные записи исключены из набора миграций. Это комплект для ревью и чистого стенда: перенос его каталога миграций поверх рабочей базы требует отдельного согласованного плана, поскольку контрольные суммы исторических файлов отличаются

Изменения публичной редакции перечислены в [составе комплекта](docs/REVIEW-EDITION.md). Статус требований отделён от статуса реализации; наличие пункта в ТЗ не означает, что он уже принят
