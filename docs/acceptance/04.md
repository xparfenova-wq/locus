# II. ЗАЩИТА ОТ ДУБЛЕЙ ВВОДОМ

### К-8. Уровень 1: совпало только имя, не показываем ничего

**На экране:** в базе десять Кать. Ввёл в поле имени «Катя», под полем
пусто, кнопка создания обычная, ничего не раскрылось

**Сервер:** GET /api/ljudi/proverka_dublej?imja=катя отдаёт
{"uroven": "net", "sovpadeniya": []} даже при десяти Катях в базе

**Число:** SELECT COUNT(1) FROM ljudi WHERE lower(imja) = 'катя' равно 10,
а число строк подсказки на экране равно нулю. Величина – пример рабочей базы, на тестовой не сверяется (отмечено 27.10)

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-9. Уровень 2: совпала фамилия, показываем список совпадений

**На экране:** ввёл фамилию «Семакин», под полем раскрылся список
с заголовком «Нашли похожих», в нём строки. Кнопка создания текст не меняет

**Сервер:** GET /api/ljudi/proverka_dublej?imja=семакин отдаёт
{"uroven": "imja", "sovpadeniya": [...]}, создание при этом разрешено

**Число:** число элементов в массиве sovpadeniya равно числу строк
под полем ввода и равно SELECT COUNT(1) FROM ljudi
WHERE lower(imja) = 'семакин', но не больше пяти

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-10. Уровень 3: совпали имя и фамилия, меняется текст кнопки

**На экране:** ввёл «Семакин Игорь» целиком, список тот же, но кнопка создания
сменила подпись на «всё равно создать», рядом «открыть её»

**Сервер:** GET /api/ljudi/proverka_dublej?imja=семакин&imja=Игорь отдаёт
{"uroven": "imya_familiya"}. Создание всё ещё разрешено, POST /api/ljudi
отдаёт 201

**Число:** SELECT COUNT(1) FROM ljudi WHERE imja_norm = 'семакин игорь' больше нуля (правка 27.10: lower() в SQLite не понижает кириллицу, норма в imja_norm) (правка 27.10: имя хранится одной строкой, два равенства разом невыполнимы), и при этом POST прошёл: COUNT стал
на единицу больше

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-11. Уровень 4: совпал телефон, жёсткая остановка

{"uroven": "kontakt", "chelovek_id": 212}. Не 201 и не 200

**Число:** SELECT COUNT(1) FROM ljudi до запроса и после равны между собой
Новой записи не появилось

### К-13. Телефон и ник это стоп, а не подсказка

**На экране:** на уровне фамилии и на уровне имени с фамилией создать можно,
на уровне телефона и ника нельзя: кнопки создания в этих двух случаях
на экране нет ни в каком виде

**Сервер:** четыре запроса подряд на один и тот же ввод: по фамилии 200
и создание разрешено, по имени с фамилией 200 и разрешено, по телефону 409,
по нику 409

**Число:** SELECT COUNT(1) FROM ljudi после двух первых попыток вырос на 2,
после двух последних не изменился

### К-14. В списке совпадений максимум пять строк

**На экране:** фамилия, по которой в базе двенадцать человек. Под полем
пять строк, не двенадцать

**Сервер:** GET /api/ljudi/proverka_dublej?imja=<эта> отдаёт массив
длиной 5, при этом в теле есть vsego = 12

**Число:** длина массива sovpadeniya равна 5, поле vsego равно
SELECT COUNT(1) FROM ljudi по этой фамилии, то есть 12

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-15. В каждой строке совпадения контекст, чтобы отличить

**На экране:** строка читается как «Семакин Игорь, Наставничество, клиент,
общались 2 дня назад». Направление, статус, давность общения, все три
на месте. Вторая строка «Семакин Игорь, Synapt, лид, не писали»

**Сервер:** каждый элемент sovpadeniya содержит napravlenie, status
и dnej_bez_obshcheniya. При отсутствии общения dnej_bez_obshcheniya = null,
и на экране это «не писали», а не «0 дней»

**Число:** dnej_bez_obshcheniya в ответе равно разнице сегодняшней даты
и MAX(kogda) по закрытым задачам этого человека, то есть 2

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-18. После «это он» всплывает плашка про задачу

**На экране:** попал в карточку 212 по кнопке «это он», сверху появилась
плашка «Поставить задачу по Игорю?» с кнопками. Это основной сценарий:
пришёл создавать человека, а нужна задача по существующему

**Сервер:** GET /api/ljudi/212?prishel_iz=proverka-dublej отдаёт
plashka_zadacha = true. При обычном заходе в карточку это поле false

**Число:** SELECT COUNT(1) FROM zadachi WHERE klient_id = 212
AND status NOT IN ('sdelano','kogda_nibud') равно нулю, поэтому плашка и появилась

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-19. Нормализация: регистр приводится к нижнему

**На экране:** в базе «Семакин», ввёл «СЕМАКИН», подсказка сработала

**Сервер:** GET /api/ljudi/proverka_dublej?imja=СЕМАКИН и
?imja=семакин отдают одинаковый массив sovpadeniya

**Число:** `select count(*) from pragma_table_info('ljudi') where name = 'imja_norm'`
равно 1, и `select imja_norm from ljudi where id = 212` отдаёт 'семакин':
нижний регистр, ё приведена к е

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-20. Нормализация: ё переходит в е

**На экране:** в базе «Семёнов», ввёл «Семенов», подсказка сработала

**Сервер:** GET /api/ljudi/proverka_dublej?imja=семенов и
?imja=семёнов отдают один и тот же непустой массив

**Число:** SELECT imja_norm FROM ljudi WHERE imja = 'Семёнов'

### К-22. Нормализация телефона: только цифры, +7 и 8 это один номер

**На экране:** в базе телефон +7 916 123-45-67. Ввёл 8 (916) 1234567,
получил жёсткую остановку по К-11

**Сервер:** POST /api/kontakty с tip = telefon и znachenie = "8(916)1234567" отдаёт 409
на запись с +79161234567

**Число:** SELECT imja_norm FROM ljudi WHERE id = 212 отдаёт
'79161234567', одиннадцать цифр без плюса и без скобок. То же значение
получается из обоих вводов
