# IV. ПЛАШКА «СЛЕДУЮЩЕЕ КАСАНИЕ»

### К-46. Плашка всплывает после действия, оставившего человека без следующего шага

**На экране:** у человека 212 ни одной открытой задачи. Поменял стадию,
внизу всплыла плашка с текстом «Создать задачу "Следующее касание
по Игорю"?» и кнопками «создать» и «не нужно»

**Сервер:** PATCH /api/sotrudnichestva/<id> отдаёт 200, в теле ответа
plashka_kasanie с полями nazvanie и srok. При наличии открытой задачи
это поле null

**Число:** SELECT COUNT(1) FROM zadachi WHERE klient_id = 212
AND status NOT IN ('sdelano','kogda_nibud') равно нулю в момент показа плашки

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-47. Триггер 1: стадия сменилась на «не сейчас», срок через месяц

**На экране:** поставил стадию «не сейчас», плашка всплыла, в названии
задачи срок через месяц от сегодня. Сегодня 19 октября, в плашке 19 ноября

**Сервер:** PATCH /api/sotrudnichestva/<id> со stadija = 'ne-sejchas'
отдаёт plashka_kasanie.srok = дата через месяц, не конец следующей недели

**Число:** значение srok в ответе равно date('now', '+1 month') и совпадает
с датой, показанной в плашке

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-48. Триггер 2: стадия сменилась на любую другую, срок конец следующей недели

**На экране:** поставил стадию «написали», плашка всплыла, срок конец
следующей недели. Сегодня 19 октября, неделя 43, срок воскресенье недели 44

**Сервер:** PATCH /api/sotrudnichestva/<id> со stadija = 'napisali' отдаёт
plashka_kasanie.srok, равный последнему дню следующей недели ISO

**Число:** srok в ответе равен воскресенью недели 44 и совпадает с датой
в плашке. Номер недели при этом вычисляется, а не берётся из поля,
см. К-173

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-49. Триггер 3: роль лид сменилась на клиент, срок конец этой недели

**На экране:** перевёл лида в клиенты, прошла анимация, плашка всплыла,
срок конец этой недели, то есть воскресенье недели 43

**Сервер:** PATCH /api/sotrudnichestva/<id> со rol = 'klient'
при прежнем 'lid' отдаёт plashka_kasanie.srok, равный последнему дню
текущей недели

**Число:** srok равен воскресенью недели 43, не недели 44. Отличается
от К-48 ровно на семь дней

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-50. Триггер 4: закрыл последнюю задачу по человеку, срок конец следующей недели

**На экране:** у человека 212 была одна открытая задача, закрыл её Плашка всплыла, срок конец следующей недели

**Сервер:** PATCH /api/zadachi/1428 со status = 'sdelano' отдаёт 200
с plashka_kasanie. При закрытии задачи, после которой остаются другие
открытые, это поле null

**Число:** SELECT COUNT(1) FROM zadachi WHERE klient_id = 212
AND status NOT IN ('sdelano','kogda_nibud') равно нулю сразу после запроса, поэтому плашка есть

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-51. Триггер 5: закрыл любую задачу по лиду, срок конец следующей недели

**На экране:** у лида 212 две открытые задачи, закрыл одну. Плашка всплыла,
хотя вторая задача ещё открыта: по лиду это срабатывает на любой задаче,
не только на последней

**Сервер:** PATCH /api/zadachi/<id> со status = 'sdelano' по задаче лида
отдаёт plashka_kasanie даже при ненулевом числе остальных открытых задач

**Число:** SELECT rol FROM sotrudnichestva по этому человеку отдаёт
'lid', и SELECT COUNT(1) FROM zadachi WHERE klient_id = 212
AND status NOT IN ('sdelano','kogda_nibud') равен 1, но плашка всё равно показана

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-52. Триггер 6: закрыл задачу «провести зум», срок конец следующей недели

**На экране:** закрыл задачу, созданную из шаблона «провести зум». Плашка
всплыла, срок конец следующей недели

**Сервер:** PATCH /api/zadachi/<id> со status = 'sdelano' по задаче
с shablon = 'provesti-zum' отдаёт plashka_kasanie

**Число:** SELECT shablon FROM zadachi WHERE id = <id> отдаёт
'provesti-zum', и срок в ответе равен воскресенью следующей недели

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-53. Все шесть триггеров проверены одним прогоном

**На экране:** шесть действий подряд на тестовых людях, после каждого
плашка показана, итого шесть показов

**Сервер:** шесть запросов, в каждом ответе plashka_kasanie не null
Сроки: у первого через месяц, у остальных пяти конец недели

**Число:** SELECT COUNT(1) FROM zadachi WHERE shablon = 'sledujushchee-kasanie'
после нажатия «создать» во всех шести случаях равно 6

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-54. Не всплывает: у человека уже есть открытая задача

не появилась ни на секунду

**Сервер:** PATCH /api/sotrudnichestva/<id> отдаёт 200

**Число:** SELECT COUNT(1) FROM zadachi WHERE klient_id = 212

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-55. Не всплывает: сотрудничество убрали в архив

**На экране:** убрала сотрудничество в архив галочкой, плашка следующего

**Сервер:** PATCH /api/sotrudnichestva/12 с arhiv: true отдаёт

прежняя

**Число:** SELECT rol, arhiv FROM sotrudnichestva WHERE id = 12 отдаёт
прежнюю роль и 1, число открытых задач ноль, показов плашки ноль

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-56. Не всплывает: плашку закрыли по этому человеку, сутки тихо

**На экране:** нажал «не нужно» по человеку 212. В течение суток любое
из шести действий по этому человеку плашку не вызывает. По человеку 213
в это же время плашка показывается

**Сервер:** POST /api/plashki/skryt с chelovek_id = 212 отдаёт 200
Следующие PATCH по этому человеку в течение 24 часов отдают
plashka_kasanie = null, по другому человеку не null

**Число:** SELECT skryto_do FROM skrytye_plashki WHERE chelovek_id = me AND o_kom_id = 212
отдаёт метку времени ровно на 24 часа вперёд от нажатия. После её истечения плашка показывается снова

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-57. Название задачи в плашке кликабельно и правится на месте

**На экране:** в плашке название «Следующее касание по Игорю» в кавычках
Нажал на него, оно превратилось в поле ввода, поправил на «Позвонить Игорю»,
нажал «создать». Создалась задача с правленым названием

**Сервер:** POST /api/zadachi с nazvanie = "Позвонить Игорю" отдаёт 201
Названия из плашки сервер не навязывает: поле приходит от клиента

**Число:** SELECT nazvanie FROM zadachi WHERE id = <новая> отдаёт
'Позвонить Игорю', не 'Следующее касание по Игорю'

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-58. Кнопка «не нужно» не создаёт задачу

**На экране:** нажал «не нужно», плашка исчезла, в списке задач человека
ничего не появилось

**Сервер:** нажатие даёт POST /api/plashki/skryt и не даёт POST /api/zadachi
В сетевой панели второго запроса нет

**Число:** SELECT COUNT(1) FROM zadachi WHERE klient_id = 212 до нажатия
и после равны

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое
