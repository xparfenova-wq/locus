# VI. ЧТО ДЕЛАЕТ АРХИВ

### К-65. Архив скрывает из списков по умолчанию

**На экране:** человек в архиве в списке Людей не показан. Включила чип
«показать архив», появился, рядом с именем его роль и дата архивации

**Сервер:** GET /api/ljudi этого человека не содержит,
GET /api/ljudi?arhiv=1 содержит, в ответе есть dostup и arhiv_s

**Число:** разница между M и N в счётчике «показано N из M» равна
SELECT COUNT(1) FROM sotrudnichestva WHERE arhiv = 1

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-66. Архив убирает из счётчиков планёрки и ОКР

**На экране:** в планёрке по Медиа число клиентов не включает архивных
В ОКР результат «10 клиентов Synapt» считает только неархивных

**Сервер:** GET /api/planerka?napravlenie=media&nedelja=43 отдаёт счётчики, посчитанные
по arhiv = 0. GET /api/okr/rezultat/<id> в поле tekushchee
то же исключение

**Число:** значение на экране равно SELECT COUNT(1) FROM sotrudnichestva
WHERE napravlenie = 'synapt' AND rol = 'klient', и при переводе одного
клиента в архив оно уменьшается на единицу

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-67. Архив убирает направление из меню

**На экране:** перевёл направление в архив, его чип исчез из второго уровня
меню и его карточка исчезла с экрана Направлений

**Сервер:** GET /api/napravlenija его не содержит. Прямой GET
/api/napravlenija/<slug> по-прежнему отдаёт 200: доступ не запрещён

**Число:** число чипов второго уровня уменьшилось с 8 до 7 и равно
SELECT COUNT(1) FROM napravlenija WHERE arhiv = 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-68. Архив не запрещает ничего: четыре случая

**На экране:** по каждому из четырёх: у человека в архиве создал задачу,
получилось; сотрудничество в архиве вернул в лида, получилось; в проекте
в архиве создал задачу и разархивировал, получилось; в направлении в архиве
сделал всё то же, получилось

**Сервер:** POST /api/zadachi по архивному человеку отдаёт 201, не 403
PATCH архивного сотрудничества со rol = 'lid' отдаёт 200. POST задачи
в архивный проект 201. Те же запросы по архивному направлению 201 и 200

**Число:** после каждого из четырёх действий SELECT COUNT(1) FROM zadachi по созданной
или изменённой записи вырос, ни один запрос не отклонён: число ответов
с кодом 403 за прогон равно нулю

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-69. Действие внутри архива возвращает человека, роль сохранена

**На экране:** у Игоря роль клиент, галочка архива стоит. администратор создала по нему задачу: задача появилась, пометка архива с карточки ушла, роль прежняя, клиент. Тост «Игорь вернулся из архива: появилась задача». Окна с вопросом не было

**Сервер:** POST /api/zadachi с nazvanie, napravlenie, otvetstvennyj и klient_id = 212 отдаёт 201, vernulsja_iz_arhiva.chelovek_id = 212 и otmena_dejstvie_id с ключом всего действия. GET /api/ljudi/212 возвращает arhiv = false; роль в GET /api/sotrudnichestva/<id> остаётся klient. Ответ 409 с вопросом не используется, поля vernut в запросе нет

**Число:** роль соответствующего сотрудничества равна klient, диалогов 0, запросов создания 1, тостов после создания 1. SELECT arhiv FROM ljudi WHERE id = 212 равно 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-70. Тост возврата откатывается кнопкой «отменить»

**На экране:** нажал «отменить» в тосте, человек вернулся в архив, созданная задача исчезла из активных. Экран вернулся в прежнее состояние

**Сервер:** POST /api/otmena с dejstvie_id = otmena_dejstvie_id из ответа К-69 отдаёт 200 и откатывает всё действие одним вызовом. Повтор этого ключа не выполняет отмену ещё раз. GET /api/otmena?dejstvie_id=<ключ> только проверяет результат. Если другой участник изменил задачу или у человека появилась новая связанная работа, ответ 409 сохраняет все изменения

**Число:** SELECT arhiv FROM ljudi WHERE id = 212 снова 1; прежняя arhiv_s восстановлена. Роль сотрудничества остаётся клиентом. SELECT COUNT(1) FROM zadachi WHERE klient_id = 212 AND COALESCE(udaleno,0) = 0 возвращается к значению до действия. Созданные записи помечены удалёнными, история сохранена. Независимая правка имени или города человека не теряется

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-71. Заранее про возврат из архива не спрашиваем

**На экране:** создал задачу по архивному человеку. Диалога «вернуть
из архива?» до действия не было: действие прошло, тост показан после

**Сервер:** POST /api/zadachi по архивному человеку выполняется
с первого раза, не отдаёт 409 с требованием подтверждения

**Число:** диалогов подтверждения до действия 0, тостов после действия ровно 1

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-72. Архив не теряет историю денег

**На экране:** сотрудничество Ассист+ в архиве, в нём суммы и платежи видны
при включённом чипе архива. Поиск по человеку его находит

**Сервер:** GET /api/sotrudnichestva/<id> по архивному отдаёт 200
со всеми суммами, не пустое тело

**Число:** SELECT SUM(summa) FROM platezhi по архивным сотрудничествам
Ассист+ больше нуля и равно сумме, показанной в карточке. Ни одна
из 270 записей не выпала: COUNT до переноса в архив равен COUNT после

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-73. Удаление помечает, а не стирает

**На экране:** удалил задачу, она исчезла из списка. Включил переключатель
«архив» на экране Задач, она появилась и открывается

**Сервер:** DELETE /api/zadachi/1428 отдаёт 200, после него
GET /api/zadachi/1428 отдаёт 200 с полем udaleno = true, а не 404

**Число:** SELECT COUNT(1) FROM zadachi WHERE id = 1428 равно 1
после удаления. SELECT udaleno FROM zadachi WHERE id = 1428 равно 1

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое
