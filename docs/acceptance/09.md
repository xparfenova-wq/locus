# VII. ЗАДАЧА: ПОЛЯ И ОБЯЗАТЕЛЬНОСТЬ

### К-74. Название единственное поле, без которого задача не сохраняется

**На экране:** в карточке создания оставил название пустым, заполнил всё
остальное, закрыл крестиком. Появился вопрос «Без названия задачу
не сохранить. Закрыть и потерять?» с кнопками «закрыть» и «вернуться»

**Сервер:** POST /api/zadachi без поля nazvanie отдаёт 400 с текстом
о названии. С названием и направлением отдаёт 201

**Число:** SELECT COUNT(1) FROM zadachi WHERE nazvanie IS NULL OR nazvanie = ''
равно 0 на всей базе

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-75. Направление обязательно у любой задачи

**На экране:** открыл создание задачи с общего экрана Задачи, направление
не выбрано, кнопка «Создать» неактивна. Выбрал направление, кнопка стала
активной

**Сервер:** POST /api/zadachi без napravlenie отдаёт 400. Текст ошибки
называет именно направление, а не «проверьте поля»

**Число:** SELECT COUNT(1) FROM zadachi WHERE napravlenie IS NULL равно 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-76. Направление подставляется из контекста экрана

**На экране:** создал задачу из направления Медиа, поле направления уже
заполнено Медиа. Создал из карточки клиента 212, заполнены клиент,
направление и проект. Создал из проекта 64, заполнены проект, клиент,
направление

**Сервер:** GET /api/kontekst?ekran=proekt&id=64 отдаёт три поля:
napravlenie, klient_id, proekt_id

**Число:** созданная из проекта 64 задача имеет те же napravlenie
и klient_id, что строка проекта 64 в таблице proekty

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-77. Ответственный обязателен и подставляется создающим

именем. Могу сменить на другого человека, очистить нельзя

**Сервер:** POST /api/zadachi без otvetstvennyj подставляет автора запроса
PATCH с otvetstvennyj = null отдаёт 400

**Число:** SELECT COUNT(1) FROM zadachi WHERE otvetstvennyj IS NULL равно 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-78. Ответственный один, второй идёт в участники

**На экране:** в поле «На ком» выбирается один человек, второй заменяет
первого. В поле «Участники» выбирается сколько угодно

**Сервер:** PATCH /api/zadachi/1428 с массивом в otvetstvennyj отдаёт 400
С массивом в uchastniki отдаёт 200

**Число:** `select count(*) from pragma_table_info('zadachi') where name =
'otvetstvennyj'` равно 1, и `select count(*) from zadacha_uchastniki where
zadacha_id = 1428` равно 3 при трёх участниках: строка на человека

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-79. Спринт обязателен, кроме статуса «когда-нибудь»

**На экране:** поставил статус «когда-нибудь», поле недели скрылось
Вернул статус «в плане», поле недели появилось и спрашивает значение

**Сервер:** POST /api/zadachi со статусом kogda_nibud без sprint отдаёт 201
Со статусом v_plane без sprint отдаёт 400

**Число:** SELECT COUNT(1) FROM zadachi WHERE sprint IS NULL
AND status != 'kogda_nibud' AND povtorjaetsja = 0 равно 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

**Число:** `select pochemu_otlozheno from zadachi where nomer = 1428` после возврата

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-84. Задачи «когда-нибудь» не попадают в недельный вид никогда

**На экране:** в разделе Задачи на неделе 43 отложенных задач нет. Включил
чип «когда-нибудь», они появились

**Сервер:** GET /api/zadachi?sprint=43 не содержит задач со статусом
kogda_nibud. GET /api/zadachi?sprint=43&kogda_nibud=1 содержит

**Число:** число строк в первом ответе равно
SELECT COUNT(1) FROM zadachi WHERE sprint = 43 AND status != 'kogda_nibud'

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-85. Незакрытая задача остаётся в списке с пометкой просрочки

**На экране:** наступил понедельник следующей недели, задача недели 43
не закрыта. Она видна в текущем списке, срок написан оранжевым
«было 15.10». Никуда не перенеслась, отдельного блока под неё нет

**Сервер:** GET /api/zadachi?sprint=44 содержит задачу недели 43 со статусом
не «сделано», с признаком prosrochena в ответе, который считается, а не хранится. Поле sprint у неё по-прежнему 43

**Число:** SELECT sprint FROM zadachi WHERE id = 1428 равно 43, а не 44:
автоперенос не произошёл

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-86. Просрочка у участника не красная

**На экране:** задача просрочена, я в ней участник, а не ответственный

moja_prosrochka = false при otvetstvennyj != me

**Число:** `select count(*) from zadachi where otvetstvennyj = me and srok <
date('now') and status NOT IN ('sdelano','kogda_nibud')` равно числу на счётчике, расхождение 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое
