# XI. АККАУНТ

### К-107. Аккаунт это канал, а не площадка

**На экране:** выбрал площадку Telegram, под ней отдельное поле аккаунта
со значением @automy_ai. Это два разных поля

**Сервер:** GET /api/zadachi/1428 отдаёт ploshadka = 'telegram'
и akkaunt_id = 7 раздельно

**Число:** `select count(*) from pragma_table_info('akkaunty') where name =
'ploshadka'` равно 1, и `select count(distinct ploshadka) from akkaunty
where id = <id>` равно 1: один аккаунт на одной площадке

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-108. Аккаунты направления лежат в карточке направления

**На экране:** открыл направление Automy, вкладка Аккаунты, в ней Telegram
@automy_ai и Instagram automy.ai

**Сервер:** GET /api/napravlenija/automy/akkaunty отдаёт массив из двух

**Число:** SELECT COUNT(1) FROM akkaunty WHERE napravlenie = 'automy' AND proekt_id IS
NULL равно двум. Величина – пример рабочей базы, на тестовой не сверяется (отмечено 27.10)

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-109. Аккаунты клиента лежат в карточке клиента

**На экране:** открыл клиента Наумову, в карточке секция Аккаунты

Каналы, где человек назначен ведущим, показаны отдельным блоком «ведёт аккаунты» и не увеличивают число аккаунтов его клиентских проектов

**Сервер:** GET /api/ljudi/212/akkaunty отдаёт массив аккаунтов этого человека

**Число:** SELECT COUNT(1) FROM akkaunty a JOIN proekty p ON p.id = a.proekt_id WHERE p.klient_id = 212 AND COALESCE(a.udalen,0) = 0 совпадает
с числом строк на экране. 212 — id человека, не проекта; сотрудник в поле vladelec не подменяет клиентскую привязку

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-110. Клиентская задача предлагает аккаунты клиента

**На экране:** создаю задачу типа «клиентская» с клиентом клиентом А,
поставил галочку публикации. В поле аккаунта список состоит только
из аккаунтов клиентом А, аккаунтов Медиалаба в нём нет

**Сервер:** GET /api/akkaunty/dlja_zadachi?tip=klientskaja&klient_id=212
отдаёт только аккаунты 212

**Число:** число строк в списке равно
SELECT COUNT(1) FROM akkaunty a JOIN proekty p ON p.id = a.proekt_id WHERE p.klient_id = 212 AND COALESCE(a.udalen,0) = 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-111. Неклиентская задача предлагает аккаунты направления

**На экране:** создаю задачу типа «бизнесовая» в направлении Automy
с галочкой публикации. В списке аккаунтов два аккаунта Automy

**Сервер:** GET /api/akkaunty/dlja_zadachi?tip=biznesovaja&napravlenie=automy
отдаёт аккаунты направления

**Число:** число строк равно SELECT COUNT(1) FROM akkaunty WHERE napravlenie = 'automy' AND proekt_id IS
NULL AND COALESCE(udalen,0) = 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-112. Единственный аккаунт подставляется молча

**На экране:** в направлении с одним аккаунтом на площадке поле заполнилось
само, выпадающий список не открывался

**Сервер:** GET /api/akkaunty/dlja_zadachi с одним результатом отдаёт его с флагом podstavit = true

**Число:** при длине массива 1 флаг true, при длине больше 1 флаг false

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-113. Отсутствие аккаунтов не блокирует создание задачи

**На экране:** у направления аккаунтов нет. Поле аккаунта пустое, рядом
ссылка «добавить аккаунт» в карточку направления или клиента. Карточка открывается в новой вкладке, черновик задачи остаётся. После добавления можно обновить список аккаунтов. Кнопка «Создать» активна и без аккаунта, задача сохраняется

**Сервер:** POST /api/zadachi с publikacija = true и без akkaunt_id
отдаёт 201

**Число:** SELECT COUNT(1) FROM zadachi WHERE publikacija = 1
AND akkaunt_id IS NULL может быть больше нуля, это не ошибка

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое
