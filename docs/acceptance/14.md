# XII. ЖУРНАЛ ИЗМЕНЕНИЙ

### К-114. Журнал одна таблица на все сущности

**На экране:** секция История событий выглядит одинаково в карточке человека,
задачи, проекта и цели

**Сервер:** GET /api/zhurnal?obekt=zadacha&id=1428 и GET /api/zhurnal?obekt=chelovek&id=212 отдают записи одного формата

**Число:** `select count(*) from sqlite_master where type = 'table' and name like 'zhurnal%'` равно 1

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-115. Запись журнала содержит семь полей

**На экране:** строка истории читается как «роль, лид на клиент, администратор,
19 октября 14:30»

**Сервер:** каждая запись GET /api/zhurnal содержит obekt, obekt_id, pole,
bylo, stalo, kto, kogda

**Число:** SELECT COUNT(1) FROM zhurnal WHERE kto IS NULL равно нулю:
безымянных изменений не бывает

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-116. В журнал пишутся семь видов изменений

**На экране:** сменил статус, стадию, ответственного, срок, сумму, привязку
к цели, архивировал. Все семь появились в истории

**Сервер:** после каждого PATCH появляется новая запись в GET /api/zhurnal

**Число:** SELECT DISTINCT pole FROM zhurnal содержит status, stadija,
otvetstvennyj, srok, summa, cel, arhiv

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-117. В журнал не пишутся описание, комментарий и заметка

**На экране:** поправил описание задачи и добавил комментарий. В истории
событий новых строк нет

**Сервер:** PATCH /api/zadachi/1428 с полем opisanie не создаёт запись
в zhurnal

**Число:** SELECT COUNT(1) FROM zhurnal WHERE pole IN
('opisanie','kommentarij','zametka') равно нулю

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-118. История событий есть в каждой сущности

**На экране:** секция История событий открывается в карточке человека,
сотрудничества, проекта, задачи и цели. В каждой она свёрнута и показывает
три последних события со ссылкой «вся история»

**Сервер:** GET /api/zhurnal?obekt=X&id=Y&skolko=3 работает для пяти значений X

**Число:** при 7 событиях в свёрнутом виде 3 строки, при 2 событиях 2 строки: минимум
из числа событий и 3

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-119. Конверсия лида в клиента считается из журнала

**На экране:** результат цели «8 новых клиентов за квартал» показывает число
и подпись «формула»

**Сервер:** GET /api/okr/rezultaty/9 отдаёт fakt и istochnik = formula

**Число:** результат с formula = novyh_klientov считает первый переход
в rol = klient у человека в направлении цели по zhurnal.obekt =
sotrudnichestvo, pole = rol. Повторный переход в клиенты не считается
вторым новым клиентом. Границы периода применяются к московской дате
первого перехода. Без полной истории дата не подменяется sozdano:
такие люди отмечены в polnota_dannyh.bez_istorii и не добавлены к подтверждённому притоку

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое
