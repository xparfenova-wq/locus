# XIV. РОЛИ И ДОСТУП

### К-126. По умолчанию все видят всё

**На экране:** новый человек без настроенных ролей видит суммы проектов,
платежи и блок Деньги в планёрке

**Сервер:** GET /api/proekty/64 без настроенной роли отдаёт поля stoimost,
vystavleno, oplacheno

**Число:** SELECT COUNT(1) FROM ljudi WHERE dostup IS NULL больше нуля,
и для них ограничений нет

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-127. Роль без денег скрывает суммы, но не проект

**На экране:** человек с ролью «без денег» открыл проект 64. Видит клиента,
направление, задачи, историю. На месте сумм строка «блок скрыт»

**Сервер:** GET /api/proekty/64 для этой роли отдаёт объект проекта, где
stoimost, vystavleno, oplacheno пустые (null), с полем skryto = ['dengi']
Разрешение конфликта с К-128 от 28.10: ключи остаются, значения пустые –
экрану нужно место под строку «блок скрыт»

**Число:** для dostup = polnyj в ответе 18 полей, для bez_deneg 15: разница ровно 3,
это summa, vyplacheno, procent

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-128. Скрытый блок не исчезает молча

**На экране:** на месте блока Деньги в планёрке стоит строка «Блок скрыт»,
а не пустота

**Сервер:** GET /api/planerka?napravlenie=synapt для роли без денег отдаёт блок dengi
со значением null и флагом skryto = true, а не отсутствие ключа

**Число:** число блоков планёрки равно 6 и для polnyj, и для bez_deneg, разница 0; суммы внутри блоков у bez_deneg скрыты

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-129. Разграничения по направлениям нет

**На экране:** человек любой роли видит все восемь направлений в меню
и задачи любого из них

**Сервер:** в API нет параметра, ограничивающего направления по человеку

**Число:** GET /api/napravlenija отдаёт 8 элементов, по числу `select count(*) from napravlenija where arhiv = 0`. Для роли polnyj и для роли bez_deneg длина массива одинаковая, разница 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-130. Роль меняют только владелец и администратор

**На экране:** в Личном кабинете обычного человека раздела с ролями нет
У Антона и администратора он есть

**Сервер:** PATCH /api/ljudi/212/dostup от человека без прав администратора отдаёт 403

**Число:** SELECT COUNT(1) FROM zhurnal WHERE pole = 'rol' AND kto NOT IN
(SELECT id FROM ljudi WHERE imja IN ('владелец','администратор')) равно нулю
Журнал хранит id человека, а не имя: сравнение со строкой
'anton' не совпадало бы никогда и критерий был бы всегда зелёным

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое
