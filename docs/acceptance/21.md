# XIX. СОХРАННОСТЬ

### К-164. Автосохранение без кнопки «сохранить»

**На экране:** поправил поле, ушёл фокусом. Внизу тост «Сохранено»
Кнопки сохранения на карточке нет

**Сервер:** PATCH уходит при потере фокуса полем, не по кнопке

**Число:** `select stadija from sotrudnichestva where id = <id>` после одного нажатия отдаёт новое значение, число подтверждающих запросов 1, диалогов 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-165. Ответ «успех» только при реальной записи

**На экране:** при обрыве связи тост «Не получилось сохранить, проверяем
связь», а не «Сохранено»

**Сервер:** PATCH отдаёт 200 только после фиксации транзакции

**Число:** при ответе 200 значение в базе изменено, расхождений нет

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-166. Правятся только переданные поля

**На экране:** поправил имя человека, телефон и почта на месте

**Сервер:** PATCH /api/ljudi/212 с одним полем не затирает остальные

**Число:** SELECT znachenie FROM kontakty WHERE chelovek_id = 212 AND tip = 'telefon' не изменилось
после правки имени

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-167. Одновременная правка сохраняет оба изменения по разным полям

**На экране:** администратор правит срок, редактор А название. Оба изменения на месте

**Сервер:** два PATCH разными полями оба отдают 200

**Число:** `select nazvanie, srok from zadachi where nomer = 1428` отдаёт оба новых значения после одного PATCH, число запросов 1

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-168. При правке одного поля двумя людьми побеждает последний, первому тост

**На экране:** редактор А видит тост «администратор изменила название, пока ты правил»

**Сервер:** второй PATCH того же поля отдаёт 200 и флаг perezapisano

**Число:** при трёх PATCH подряд `select nazvanie from zadachi where nomer = 1428` равно значению третьего, потерянных правок 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-169. Отмена действия тостом пять секунд

**На экране:** закрыл задачу, внизу «Задача закрыта. [отменить]»
Через пять секунд тост исчез

**Сервер:** POST /api/otmena с id действия возвращает прежнее значение

**Число:** `select status from zadachi where nomer = 1428` после отмены равен v_processe, то есть значению до закрытия, расхождение 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-170. Экран отстаёт от базы не больше чем на 30 секунд

**На экране:** коллега изменил задачу, через 30 секунд изменение видно
без перезагрузки

**Сервер:** опрос раз в 30 секунд

**Число:** при приёмке число на экране сверяется с базой после обновления
страницы, расхождение в пределах 30 секунд не считается ошибкой

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое
