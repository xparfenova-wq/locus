# XXVI. ИМПОРТ, ЭКСПОРТ И ПЕРЕНОС

### К-225. Выгрузка в таблицу по фильтру

**На экране:** применил фильтры, нажал «Выгрузить», получил csv
с теми же строками

**Сервер:** GET /api/vygruzka?tip=zadachi с теми же параметрами, что и список

**Число:** строк в файле 42 плюс 1 заголовок, на экране 42, расхождение 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-226. Выгружаются задачи, люди и деньги

**На экране:** три пункта выгрузки

**Сервер:** tip принимает zadachi, ljudi, dengi

**Число:** число столбцов в файле равно `select count(*) from pragma_table_info('proekty')`, расхождение 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-227. Загрузка проверяет перед записью

**На экране:** загрузил файл с ошибками, увидел отчёт до записи
и кнопку подтверждения

**Сервер:** POST /api/zagruzka?proverka=1 отдаёт отчёт без записи

**Число:** при proverka=1 число записей в базе не меняется

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-228. Справочники переносятся автоматически

**На экране:** после переноса в Локусе все люди, контакты, направления
и аккаунты из старой базы

**Сервер:** скрипт переноса отдаёт отчёт «было, доехало, расхождение»

**Число:** число людей в новой базе равно числу в старой, расхождение
ноль или объяснено в отчёте

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-229. Состояние переносится с валидацией

**На экране:** администратор видит список активных клиентов и проектов
с предложением подтвердить каждый

**Сервер:** перенос состояния идёт через отдельный адрес, не автоматом

**Число:** подтверждено 4, перенесено 4, расхождение 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-230. История не переносится, старый Локус доступен на чтение

**На экране:** закрытых задач старой системы в новой нет. Ссылка
на старый Локус работает

**Сервер:** в новой базе нет записей с датой раньше даты запуска,
кроме справочников

**Число:** SELECT COUNT(1) FROM zadachi WHERE sozdano < дата_запуска
равно нулю

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-231. Бэкап проверяется восстановлением

**На экране:** не применяется

**Сервер:** ежесуточный бэкап, проверка восстановлением в сторону

**Число:** `select count(*) from zadachi` в восстановленной копии равно значению в боевой на момент снимка, расхождение 0. Наличие файла бэкапа без этой
проверки не засчитывается
