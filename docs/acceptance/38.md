# XXXVII. РЕФЕРАЛЫ

### К-269. Реферал это роль сотрудничества, не отдельная сущность

**На экране:** у человека создаётся сотрудничество с ролью «реферал»
рядом с лидом и клиентом. Один человек бывает рефералом по Медиа
и клиентом по Synapt одновременно

**Сервер:** POST /api/sotrudnichestva принимает rol = referal

**Число:** `select count(distinct rol) from sotrudnichestva` не больше 3, значения
только lid, klient, referal. Вхождений слова «партнёр» на 14 экранах 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-270. Клиент и реферал в одном направлении

**На экране:** у клиентского сотрудничества есть галочка «приводит клиентов»
Поставил, появились поля процента и договора. Человек виден
и в фильтре «клиенты», и в фильтре «рефералы»

**Сервер:** PATCH /api/sotrudnichestva/{id} с privodit_klientov=true
при status=klient

**Число:** один и тот же chelovek_id попадает в выдачу обоих фильтров: пересечение множеств равно 1 элементу

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-271. Стадии реферала

**На экране:** договариваемся, работаем, пауза. Стадий лида у него нет
У каждой стадии подписано следующее действие

**Сервер:** справочник стадий зависит от статуса

**Число:** `select count(*) from spravochnik_stadij where rol = 'referal' and gotovyj = 1` равно 4: присматриваемся, договариваемся, работаем, к выплате. Стадий «познакомились» и «привёл» 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-272. Приведённые считаются сами по источнику

**На экране:** в карточке реферала список тех, у кого в источнике стоит он Поля для ручного ввода числа приведённых нет

**Сервер:** GET /api/sotrudnichestva/{id}/privedeno отдаёт список и суммы

**Число:** privedeno равно `select count(*) from sotrudnichestva where istochnik =
'rekomendacija' and rekomendoval_id = 212`, расхождение 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-273. Заработано считается по оплаченным счетам

**На экране:** «заработано 190 000 ₽» рядом со списком приведённых

**Сервер:** сумма счетов с заполненной датой оплаты по проектам приведённых

**Число:** `select sum(summa) from platezhi where oplachen_at is not null` равно
показанному заработанному, расхождение 0; после добавления платежа без
oplachen_at число не меняется, разница 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-274. К выплате считается формулой, руками не вводится

**На экране:** «к выплате 18 836 ₽». Поля для ручного ввода этой суммы нет

**Сервер:** k_vyplate = zarabotano × procent / 100 − vyplacheno

**Число:** заработано 190 000, процент 14, выплачено 7 764, к выплате 18 836

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-275. Выплаченное вносится руками и уменьшает к выплате

**На экране:** кнопка «отметить выплату», вносится сумма и дата. После этого
«к выплате» уменьшилось ровно на внесённую сумму, видна дата последней выплаты

**Сервер:** POST /api/sotrudnichestva/{id}/vyplata с суммой и датой

**Число:** было к выплате 18 836, внесли 10 000, стало 8 836

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-276. Процент шкалой: сумма не считается

**На экране:** процент задан текстом «14 / 9 / 6 по порогам». Вместо суммы
к выплате показана шкала и заработанное, пометка «сумму считает человек»

**Сервер:** k_vyplate приходит пустым, если procent не число

**Число:** попыток подставить формулу в текстовую шкалу 0 при 3 проверках из 3

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-277. Шаблоны задач по выплате

**На экране:** приведённый оплатил, появилось предложение создать две задачи:
подготовить закрывающий акт и выплатить процент с суммой в названии
Задачи не созданы, пока не нажали

**Сервер:** задачи создаются только по действию человека

**Число:** создано ровно 2 задачи, у обеих srok равен пятнице следующей недели,
otvetstvennyj равен тому, кто ведёт направление, расхождение 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-278. Договор хранится ссылкой

**На экране:** в сотрудничестве поле «ссылка на договор», открывается
в новой вкладке. Загрузки файла нет. Это же поле есть у клиентского
сотрудничества

**Сервер:** dogovor_id это ссылка на запись в dokumenty, не адрес и не файл. Сам адрес хранится в поле ssylka того документа

**Число:** `select count(*) from dokumenty where fajl is not null and tip = 'dogovor'` равно 0: договор только ссылкой

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-279. Рассылка рефералам отличается от клиентской

**На экране:** при создании рассылки выбирается тип «рефералам»,
корзина отдельная

**Сервер:** рассылка с типом referal не попадает к людям со статусом
лид или клиент, если у них нет признака «приводит клиентов»

**Число:** пересечение множеств id двух корзин равно 0 элементов

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-280. Фильтры в Людях по типу и по рассылкам

**На экране:** в Людях фильтры: клиент, лид, реферал, архив. Отдельно фильтр
по рассылкам: кому отправляли, кто ответил, кто не получал

**Сервер:** GET /api/ljudi?rol=referal и ?rassylka={id}

**Число:** сумма по трём фильтрам роли плюс люди без сотрудничеств равна `select count(*) from ljudi`, расхождение 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое
