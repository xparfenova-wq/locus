# XXXIX. УСЛУГА, ВНЕШНИЕ ID, НИКИ

### К-286. У проекта услуга выбирается из услуг своего направления

**На экране:** поле «услуга» открывается раскрывающимся списком. В проекте
Медиа предлагаются съёмка, ведение соцсетей, стратегия. AI-чекап
не предлагается, он у Synapt. Последняя строка списка «своё значение»

**Сервер:** PATCH /api/proekty/{id} принимает usluga_id. Услуга чужого
направления отдаёт 400 с текстом «услуга другого направления»

**Число:** равно `select count(*) from uslugi where napravlenie = 'synapt' and arhiv =
0`, расхождение 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-287. Выгрузка проектов отдаёт всё для сверки с финмоделью

**На экране:** в разделе денег кнопка «выгрузить проекты», выбор периода,
скачивается файл

**Сервер:** GET /api/vygruzka?ot=2026-10-01&do=2026-10-31 отдаёт CSV
с колонками: номер, название, клиент, направление, услуга, стоимость,
платежи с датами

**Число:** строк в файле равно `select count(distinct proekt_id) from platezhi where
oplachen_at between <начало> and <конец>`, расхождение 0; столбцов с внешним
id в файле 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-288. Ник Телеграма это обычный контакт, не обязательное поле

**На экране:** человека можно создать и сохранить без ника. Если ник есть,
он показан строкой контакта со ссылкой, открывающей t.me/igor_s

**Сервер:** POST /api/ljudi без контакта типа telegram отдаёт 200

**Число:** `select count(*) from ljudi l where not exists (select 1 from kontakty k
where k.chelovek_id = l.id and k.tip = 'telegram')` равно 312 до и 312
после, разница 0; заблокированных карточек 0. Величина – пример рабочей базы, на тестовой не сверяется (отмечено 27.10)

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое
