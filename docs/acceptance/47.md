# XLVII. ПОЛЯ: КАЖДОЕ ПОЛЕ КАЖДОЙ ТАБЛИЦЫ

Проверка на уровне поля: допустимое значение, недопустимое, пустое,
граница длины, и отдельно что вычисляемое поле руками не пишется

### К-356. Сотрудничество получает id само, руками его не задать

**На экране:** в форме нового сотрудничества у администратора нет поля id, в карточке id виден только мелким серым текстом без возможности правки

**Сервер:** POST /api/sotrudnichestva с телом, где передан id: 77, отдаёт 201 и новый id, выданный сервером, не 77. PATCH с полем id отдаёт 400 с текстом, что id менять нельзя

**Число:** `SELECT COUNT(*) FROM sotrudnichestva WHERE id = 77` даёт 0, если 77 не выдавался сервером. Два подряд созданных сотрудничества имеют разные id

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

**Число:** `SELECT COUNT(*) FROM sotrudnichestva WHERE chelovek_id IS NULL OR chelovek_id NOT IN (SELECT id FROM ljudi)` равно 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-364. Стадия зависит от статуса, чужая стадия отклоняется

**На экране:** у лида в списке стадий пять пунктов: не писали, написали, на согласовании, ждём оплату, не сейчас. У клиента шесть: в работе, ждём оплату, на согласовании, ждём обратную связь, запланирован зум, пауза. У реферала четыре: присматриваемся, договариваемся, работаем, к выплате. Паузы у реферала нет, пунктов другой роли в списке нет

**Сервер:** PATCH для status klient со stadija: v_rabote отдаёт 200. PATCH для status lid со stadija: v_rabote отдаёт 422 с текстом, что стадия не подходит статусу. Для referal со stadija: rabotaem отдаёт 200, со stadija: ne_pisali отдаёт 422

**Число:** `SELECT COUNT(*) FROM sotrudnichestva WHERE rol = 'lid' AND stadija NOT IN ('ne_pisali','napisali','na_soglasovanii','zhdem_oplatu','ne_sejchas')` равно 0, такие же проверки по клиенту и рефералу тоже дают 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое
