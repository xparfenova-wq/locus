### К-876. Роль живёт у сотрудничества, а не у человека

**На экране:** открываю карточку Игоря Соколова. В шапке карточки нет ни слова про роль: нет плашки клиент, нет плашки реферал, нет выпадающего списка роли. Роль вижу только в шапке каждого блока направления, ниже разделителя

**Сервер:** GET /api/ljudi/{id} отдаёт объект человека с полями imja, yurlico, kontakty, istochnik и массивом sotrudnichestva. Поля status и stadija на верхнем уровне объекта нет совсем, они есть только внутри элементов sotrudnichestva

**Число:** в ответе GET /api/ljudi/{id} поиск по ключам верхнего уровня даёт 0 вхождений status и 0 вхождений stadija. SELECT count(*) FROM pragma_table_info('ljudi') WHERE name IN ('status','stadija') даёт 0

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-877. Клиент по одному направлению и реферал по другому это два сотрудничества

**На экране:** у Игоря Соколова два блока. Первый блок Synapt, в шапке плашка клиент, стадия в работе. Второй блок Медиа, в шапке плашка реферал, стадия работаем. Между блоками горизонтальный разделитель на всю ширину

**Сервер:** GET /api/ljudi/{id} отдаёт sotrudnichestva из двух элементов: {napravlenie:"synapt", rol:"klient", stadija:"v_rabote"} и {napravlenie:"media", rol:"referal", stadija:"rabotaem"}. У каждого свой непустой id

**Число:** SELECT count(*) FROM sotrudnichestva WHERE chelovek_id={id} AND arhiv=0 даёт 2, SELECT count(DISTINCT napravlenie) по этим же строкам даёт 2

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-878. Два сотрудничества по разным направлениям ведут свои стадии независимо

**Сервер:** PATCH /api/sotrudnichestva/{id_synapt} с телом {stadija:"na_soglasovanii"} отдаёт 200. Повторный GET /api/ljudi/{id} показывает stadija na_soglasovanii у элемента synapt и stadija rabotaem у элемента media, у второго элемента поля obnovleno и poslednee_obshenie не изменились

**Число:** до правки и после снимаю `SELECT stadija, poslednee_obshenie FROM sotrudnichestva WHERE chelovek_id = 1 AND napravlenie = 'media'`, обе величины совпадают посимвольно

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-879. Клиент и реферал в одном направлении это одно сотрудничество с признаком

### К-880. Признак privodit_klientov ставится и снимается галочкой

**На экране:** в блоке Synapt жму три точки, Редактировать. В форме галочка приводит клиентов. Ставлю, появляются поля процента и номера договора. Сохраняю, в шапке блока возникает серая надпись приводит клиентов. Снимаю галочку, надпись исчезает, подблок приводит скрывается

**Сервер:** PATCH /api/sotrudnichestva/{id} с {privodit_klientov:true, procent:10} отдаёт 200 и объект с privodit_klientov true. PATCH с {privodit_klientov:false} отдаёт 200, поля procent и dogovor_nomer сохраняются в базе, но в ответе карточки блок privodit не отдаётся

**Число:** SELECT privodit_klientov FROM sotrudnichestva WHERE id={id} даёт 1 после первого запроса и 0 после второго, при этом SELECT procent не стал NULL, значение 10 на месте

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое
