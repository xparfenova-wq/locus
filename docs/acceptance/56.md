# LV. РАССЫЛКИ ПО НЕДЕЛЯМ И ЗАКРЫТИЕ ПРОЕКТА

### К-1373. Два счётчика рассылки живут раздельно и не складываются друг с друга

**На экране:** в карточке рассылки Школы Москвы администратор видит два числа подряд, в базе 500 из 500 собрано и отправлено 310 из 500. Числа стоят в разных строках, у каждого своя подпись, нигде нет суммы 810 и нигде нет одного общего числа вместо двух

**Сервер:** GET /api/rassylki/{id}/svodka отдаёт объект с двумя независимыми полями, kontaktov_v_baze 500 и otpravleno 310, плюс plan_vsego 500. Поля не вычисляются одно из другого, сервер не возвращает поле vsego_summa

**Число:** два запроса к базе, select count(*) from rassylka_ljudi where rassylka_id = {id} даёт 500, select count(*) from rassylka_ljudi where rassylka_id = {id} and status = 'otpravleno' даёт 310. Приёмка проходит, когда оба числа на экране совпадают с выдачей этих двух запросов до единицы

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-1374. Счётчик контактов в базе считается запросом, а не хранимым полем

**Сервер:** GET /api/rassylki/{id}/svodka после вставки 20 строк отдаёт kontaktov_v_baze 520 без отдельного вызова пересчёта. В таблице rassylka нет колонки kontaktov_cached, которую пришлось бы обновлять

**Число:** select count(*) from rassylka_ljudi where rassylka_id = {id} равен 520, и равен числу на экране. Контрольная проверка, прямая вставка строки в базу минуя интерфейс тоже поднимает экранное число на единицу

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое

### К-1379. Процент выполнения недели берёт фактом только отправки этой недели

**Число:** недельный факт считается с фильтром по дате перехода в статус, `select count(*) from rassylka_ljudi where rassylka_id = 17 and status = 'otpravleno' and otpravleno_at >= '2026-10-19' and otpravleno_at <= '2026-10-25'` недели 44, равен 30. Накопительный без фильтра по дате равен 55

**Две ширины:** проверяется на 1440 и на 390, поведение одинаковое
