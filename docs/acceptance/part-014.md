**На экране:** с телефона линейка чипов все, школы Москвы, 500, 1С-франчайзи, 240, преподаватели, 180 прокручивается вбок одним жестом, чипы не переносятся в три этажа и не сжимаются до неузнаваемости. Нажатый чип визуально отличается от остальных

**Сервер:** GET /api/rassylki/{id}/ljudi отдаёт все чипы одним ответом, без постраничности для линейки

**Число:** высота линейки чипов одна строка, не больше 56 px при трёх чипах на ширине 390 px. Число чипов на экране равно числу записей в ljudi

### К-843. Фильтр по статусу в рассылке существует отдельно от чипа, веб

**На экране:** при нажатом чипе школы Москвы участница Б открывает фильтр По статусу в рассылке и выбирает Ответил. В списке остались только ответившие, чип при этом остался школы Москвы, 500, число на чипе не изменилось

**Сервер:** GET /api/ljudi?rassylka_id={id}&status=otvetil отдаёт только ответивших. Параметры rassylka_id и status независимы, оба в запросе

**Число:** число строк равно `select count(*) from rassylka_ljudi where rassylka_id = {id} and status = 'otvetil'`. Число на чипе остаётся 500

### К-844. Фильтр по статусу в рассылке существует отдельно от чипа, телефон

**На экране:** с телефона фильтр По статусу в рассылке открывается шитом, варианты не писали, отправлено, ответил, отказался крупными строками. После выбора Ответил шит закрывается, под линейкой чипов висит плашка выбранного статуса с крестиком, чтобы снять

**Сервер:** тот же GET /api/ljudi?rassylka_id&status. Снятие плашки повторяет запрос без параметра status

**Число:** после снятия статуса число строк возвращается к 500. Плашка выбранного статуса на экране ровно одна, не дублируется при повторном выборе
