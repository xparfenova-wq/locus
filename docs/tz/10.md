# ЧАСТЬ V-Б. МИГРАЦИИ СХЕМЫ

Структура базы будет меняться после запуска. Чтобы менять её, не ломая
данные, все изменения идут пронумерованными файлами

```
migrations/
  001_pervaja_shema.sql
  002_pole_slozhnost.sql
  003_tablica_grafik.sql
```

**Как работает:** система хранит номер последней применённой миграции
При запуске накатывает только новые

**Правила:**

```
миграции не правятся задним числом, только новые поверх
каждая миграция имеет обратную, для отката
перед накатом снимок базы
накат сначала на копии, потом на боевой
```

**Что нельзя делать без отдельного решения:**

```
удалять колонку с данными
менять тип поля, если в нём уже есть данные
переименовывать таблицу
```

Такие изменения делаются в три шага: добавить новое, перенести данные,
удалить старое отдельной миграцией через неделю
