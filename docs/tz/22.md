# ЧАСТЬ XIII. БОТ В ТЕЛЕГРАМЕ

Второй шаг после самого Локуса. Но проектируется сразу, потому что от этого зависит
устройство API

## Зачем

Команда работает через Клода и через Телеграм. Если ввод возможен только через форму
в браузере, его не будет: это доказано, 505 людей без единого касания

Бот это второй вход в те же данные. Не отдельная система, а клиент того же API

## Что умеет

### Задачи

```
создать      «КП Газизову до пятницы редактор А» разбирается в задачу
посмотреть   «мои задачи» отдаёт список на неделю
изменить     нажал на задачу в списке, поменял статус кнопками
закрыть      одной кнопкой из списка
удалить      с подтверждением
```

### Люди

```
найти        «клиент А» отдаёт карточку: статус, стадия, дни молчания, следующий шаг
касание      «записал касание с клиентом А, обсудили медиа» создаёт запись
стадия       кнопками из карточки
```

### Напоминания

| Когда | Что |
|---|---|
| Понедельник утром, лично | твои задачи на неделю, что просрочено |
| Понедельник утром, в общий чат | сводка планёрки, цели и движение |
| Ежедневно, лично | если есть просроченное |
| По событию, лично | назначили задачу, упомянули в комментарии |
| Пятница, лично | кому не писал больше двух недель |

Частота настраивается в Личном кабинете, каждый сам решает, что получать

### Зум и фоллоуап

Отправил в бот расшифровку зума, бот возвращает список задач-кандидатов и решений
Отмечаешь галочками, что взять, остальное отбрасывается

Это снимает 20-40 минут ручной сборки на каждый зум

## Как устроен

**AI-слой обязателен.** Иначе бот превращается в меню из кнопок, которым пользоваться
дольше, чем открыть браузер

```
человек пишет свободным текстом
   ↓
модель разбирает: что за действие, какие сущности
   ↓
бот показывает, что понял, чипами
   ↓
человек подтверждает или правит
   ↓
запись через тот же API
```

**Ключевое правило: бот не угадывает молча.** Всегда показывает, что понял,
до записи. «Создаю задачу: КП для Дениса Газизова, до пятницы 24.10, редактор А. Верно?»

## Что нужно от API

Бот это тот же клиент, что и браузер. Поэтому в API нужны:

- разбор строки в задачу отдельным вызовом, чтобы один код работал в палитре и в боте
- пакетная запись для расшифровок зумов
- ключ повтора: отправил расшифровку дважды, дубли не появились
- вызов «что у меня на неделю» и «кому давно не писал»

## Чего бот не делает

- не показывает отчёты и дашборды, для этого есть Локус
- не редактирует цели и результаты ОКР, это работа на экране
- не работает с файлами

## Порядок

Бот делается после того, как Локус работает и API устоялся. Раньше смысла нет:
каждая правка API ломала бы бота


## Уточнение надёжности создания контакта, 15 ноября 2026

Повторное нажатие добавления во время сохранения не отправляет вторую
запись. Если ответ о создании потерян, интерфейс проверяет наличие
контакта у того же человека и того же вида. Повторная явная попытка
тоже начинается с чтения. Совпадение подтверждает существование записи,
но не устанавливает автора её создания. Ошибка чтения сохраняет
введённый текст и не выдаётся за успех. Истечение сессии требует
повторного входа и нового явного сохранения

Для этой проверки существующий GET /api/kontakty/duplikaty принимает
отдельный режим с podtverdit_chelovek_id, tip и znachenie. Все три поля
обязательны, остальные параметры в этом режиме запрещены. Результат
содержит только контакты указанного владельца, вида и нормализованного
значения, включая их id и versija. Пустой запрос в этом режиме не превращается в отчёт по всей базе. Обычный режим поиска дублей сохраняет
прежнюю семантику исключения своего человека

Одинаковый непустой нормализованный контакт одного человека и вида
защищён уникальным индексом базы. Этот пункт не означает приёмку
отдельных требований о межличностных дублях, force или преобразовании
ссылок Telegram: они проверяются своими сценариями


## Контакты: нормализация и отмена, 15 ноября 2026

Общий ключ Telegram распознаёт @Nick, t.me/nick и публичную ссылку
http[s]://t.me/nick, включая завершающий слеш, параметры и фрагмент
Распознаются публичные имена из латинских букв, цифр и подчёркиваний;
неизвестные формы ссылок не подменяются вымышленным именем. Исходный
ввод сохраняется отдельно от вычисленного ключа

Указание контакта, уже существующего у другого человека, вызывает
предупреждение со ссылкой на владельца до сохранения. Обычные POST
и изменение значения, вида или владельца через PATCH возвращают 409,
поле dubl_chego содержит ID владельца, dubli содержит список владельцев
Явный force: true разрешён для контакта уже существующего человека;
строки, числа и другие подмены логического флага отвергаются. Один
контакт одного человека всё равно защищён уникальным индексом
Создание нового человека со совпавшим контактом остаётся запрещённым,
вложенный force не принимается. Существующие совместно используемые
контакты разных людей не объединяются автоматически

DELETE контакта возвращает deleted, token_otmeny и novyj_osnovnoj
Отмена принимает только серверный токен. Исходная строка, её ID,
порядок, значение и участник берутся из серверной квитанции в базе;
передать или подменить их в теле отмены нельзя. Квитанция действует
30 секунд и переживает перезапуск приложения. Повтор тем же токеном
подтверждает уже возвращённую строку; новая правка или повторное
удаление не перезаписываются. Возвращённая запись получает новую
версию, поэтому прежняя вкладка не может незаметно её переписать
Сбой журнала откатывает возврат и перенос основного целиком

Контакт удаляется и возвращается без пересборки всей карточки
Действие «Вернуть» показано семь секунд. При потере ответа возврата
доступна явная проверка тем же токеном; повторного автоматического
восстановления после нового входа нет. Мобильный свайп удаления
проверяется отдельным сценарием и этим уточнением не считается принятым


## Мобильное удаление и проверка ответа, 15 ноября 2026

На телефоне свайп контакта влево открывает одно действие «Удалить»
с областью от 44 px. Сам жест не удаляет контакт. Свайп вправо и Escape
закрывают действие; вертикальная прокрутка, одиночное копирование
и двойное касание для редактирования сохраняются. На вебе крестик
доступен по наведению и клавиатурному фокусу

Карточка передаёт с DELETE случайный ключ одного действия, увиденную
версию, исходного человека и вид контакта. Ключ хранится в серверной
квитанции как SHA256. Потерянный ответ не объявляется неудачным удалением:
доступно отдельное действие проверки. Проверка DELETE с proverit: true
и исходным zapros_kljuch только уточняет результат; при отсутствии
совершённого удаления она не удаляет существующую строку

Подтверждённое удаление можно проверить после перезапуска и получить
новый токен возврата с исходным сроком действия. Прежний токен также
остаётся действительным. Дополнительные проверки не повторяют удаление
и запись журнала. Если запись уже возвращена, проверка сообщает её наличие. Обычное повторное удаление отсутствующего ID возвращает 404;
повтор старого действия после возврата не удаляет строку заново

Ключ не может использоваться для другого контакта или версии
Изменение владельца или вида контакта не разрешается обходить через
неявную смену версии. После явного разрешения обычного конфликта
проверка использует именно версию отправленного запроса. Если окно
возврата истекло, отсутствие контакта можно подтвердить без обещания
недоступной отмены. Проверка не переносит в новый запрос бизнес-удаление
и не выполняется автоматически после повторного входа

### Порядок контактов: атомарное сохранение

Порядок меняется прямо в карточке: мышью за ручку строки или долгим
тапом на телефоне. Линия показывает место вставки. Отмена и перенос
на прежнее место не пишут; завершённый жест отправляет один запрос
Окно с кнопками вверх и вниз и клавиатурой остаётся дополнительным способом
Основные метки и значения контактов при этом сохраняются
Если основной не выбран, первый по новому порядку используется в списке людей

GET /api/kontakty/porjadok?chelovek_id=N возвращает spisok и kontekst
одного снимка. POST того же адреса принимает chelovek_id, kontekst и porjadok – полный массив ID только этого человека. Все изменения порядка,
версий и журнала применяются одной транзакцией; ошибка откатывает всё
Чужая правка, добавление или удаление контакта после прочитанного снимка
возвращает 409 с tekuschij_porjadok. При изменении состава сначала требуется
загрузить список; автоматической перезаписи нет. После потерянного ответа
результат проверяется чтением, POST автоматически не повторяется

Адрес из К-1371: GET/PATCH /api/ljudi/N/kontakty/porjadok использует тот же снимок и ту же транзакцию. PATCH принимает kontekst и porjadok; человек
определён адресом. Противоречивый chelovek_id отклоняется. Прямой жест
использует версии уже показанных строк; свежие непрочитанные версии
не подставляются перед сохранением. При конфликте сначала загружаются
актуальные контакты, повторный жест требует отдельного действия
После потери ответа проверка только читает. Ошибка проверки сохраняет
видимые контакты и кнопку проверки, включая перерисовку карточки

### Телефон: общий разбор и показ

Форма и сервер используют один разбор и один каталог масок. Явный плюс
сохраняет международный код; правило российской восьмёрки применяется
только к местному вводу без плюса. Частичная вставка внутри номера
сохраняет остальные цифры. Запоздавший ответ разбора не меняет новый ввод
или следующую форму после закрытия прежней

Страна и bez_maski передаются как параметры ввода при POST/PATCH контакта,
не как дополнительные колонки. Выбранная страна проверяет код и длину по её маске. Без маски не добавляется код России, а хранение остаётся общим:
плюс и все введённые цифры без пробелов и скобок. Перед созданием проверка
контакта использует те же параметры и возвращает подготовленное znachenie,
поэтому подтверждение потерянного ответа не создаёт повторную запись

GET контактов возвращает производное pokaz по общему справочнику;
primary_phone сохраняет международное значение, primary_phone_pokaz
предназначен для подписей при выборе человека. Телефон показан с маской
в карточке, списке, выборе порядка и сравнении конфликтов; ссылка tel
использует международные цифры. Неопознанный или ранее некорректный контакт
показывается буквально, без выдуманных цифр и без перезаписи старой строки


### Уточнение выгрузки карточки человека, 15 ноября 2026

Кнопка «выгрузить JSON» в карточке скачивает актуальный согласованный снимок из GET /api/ljudi/{id}/celikom. Формат locus-person-card-v1 содержит schema с названиями таблиц разделов и data с доступными участнику данными карточки. Контакты сохраняют серверный порядок, znachenie телефона хранит международное значение, pokaz остаётся производным. Рабочая база и данные входа не выгружаются. Открытая правка или неподтверждённое сохранение сначала завершаются


### Общая отмена по журналу: версии и границы команды

POST /api/otmena принимает zhurnal с разными ID записей либо dejstvie_id
из контекста журнала. Без параметров выбирается последняя серверная
команда участника. Ключ команды объединяет её записи даже при разных
миллисекундах и не объединяет разные запросы с одинаковым временем
Старым записям ключ и версия не придумываются

Отмена проверяет именно изменяемые поля и привязки. Более поздняя
правка того же поля, включая уход и возврат значения через API или SQL,
даёт 409. Независимая правка другого поля сохраняется и не мешает
отмене. Все выбранные изменения применяются одной транзакцией через
обычные проверки сущностей; ошибка не оставляет частичной отмены
Связанные поля человека, проекта и роли у задачи проверяются вместе,
номер недели и ISO-год остаются одной парой. Срок задачи не подменяет
самостоятельно выбранный спринт

Чужие записи журнала не отменяются. Ограничения денег и прав графика
действуют и на отмену. Неверный или неизвестный параметр не приводит
к отмене другого последнего действия. По одной цели поля выбирается
одна последняя правка; неизвестная цепочка старых версий не угадывается
Отмена создания, отметок повторения и других составных действий требует
их предметной команды: общий журнал не выдаёт частичный откат за полный


### Платёжная команда: версии, остаток и проверка результата

Платёж и аккаунт соцсетей имеют служебную versija. PATCH использует
показанную версию поля и связанных владельцев, DELETE подтверждённую
версию целой строки. Чужая правка и уход с возвратом не перезаписываются

Предпросмотр оплаты показывает versija. POST prishlo получает её,
summa_fakt (старое имя summa совместимо), data и reshenie. Для частичной
оплаты решение обязательно: otdelnoj_strokoj или spisat. Без решения 409
nuzhen_vybor до любой записи. Оплата, остаток и закрытие связанных задач
сохраняются одной транзакцией. Дата существует в календаре, сумма
конечная и положительная. Пустой или неизвестный параметр не игнорируется

zapros_kljuch обязателен для обеих платёжных команд; это случайный UUID одного намерения. Тот же участник,
платёж, вид команды и содержание дают ту же квитанцию после перезапуска
Изменение содержания или объекта с тем же ключом даёт конфликт
GET /api/platezhi/{id}/proverka?zapros_kljuch=... только проверяет квитанцию
Потерянный ответ не вызывает автоматического POST: остаётся явная
проверка. Отрицательная проверка разрешает отдельный явный повтор
с тем же ключом. Квитанция подтверждает прежнюю запись, текущее состояние
после неё читается отдельно. Права на суммы проверяются заново

Отмена из тоста передаёт ключ исходной команды и собственный ключ
намерения. Она возвращает исходный платёж, удаляет созданный остаток
и возвращает статусы закрытых этой командой задач одним действием
Любая последующая правка затронутого состояния даёт конфликт до записи
Самостоятельное снятие оплаты без ключа исходной команды снимает только
oplachen_at у текущего платежа по показанной версии


### Отмена создания задачи и автоматического возврата из архива

POST /api/zadachi возвращает otmena_dejstvie_id. POST /api/otmena
с этим dejstvie_id одним действием мягко удаляет все созданные этой
командой задачи и возвращает прежние архивные флаги и даты людей
Роли не меняются. Новая правка задачи или её связей, новая работа
у возвращённого человека и изменение архива блокируют весь возврат
Независимая правка имени или города человека сохраняется

GET /api/otmena?dejstvie_id=... только проверяет, была ли эта отмена
подтверждена. Сбой ответа не вызывает автоматического POST. Повтор
подтверждённой отмены возвращает квитанцию без второй записи; последующая
работа не отменяется повторно. История создания и удаления сохраняется
DELETE обычной задачи требует показанную versija и пишет внутренний id
в журнал. Номер задачи остаётся только ключом её публичного адреса

### 16 ноября 2026: повтор первоначального создания задачи

## Уточнение реализации 21 ноября: личное откладывание инсайта

В текущей планёрке сначала видны пять актуальных причин; «ещё» раскрывает все оставшиеся, без скрытого ограничения десятью на тип.
