## 4ж. Комментарии: упоминания и вложения

### Упоминание человека

В комментарии можно позвать человека через собачку:

```
@участница Е посмотри, пожалуйста, второй вариант
```

Что происходит:

```
упомянутому      уведомление в поток «Про меня», бот пишет
в комментарии    имя подсвечено и кликабельно, ведёт в карточку человека
в задаче         упомянутый добавляется в участники, если его там не было
```

### Время комментария

У каждого комментария видно, кто и когда:

```
администратор, вчера 14:30
участница Е П, 10 минут назад
```

Свежее время показывается относительно («10 минут назад»), старше суток
датой и временем

### Правка и длинные обсуждения

Изменить и удалить реплику может только её автор. После правки видна
пометка «изменено», время создания остаётся прежним. Правка из старой
вкладки требует сравнения с сохранённым вариантом и явного решения

Упоминание хранит выбранного человека, а не поиск по текущему имени
При совпадении имён выбирается конкретный участник команды. Смена имени
не переводит прежние ссылки на тёзку. Старые тексты без достоверной
привязки не назначаются людям задним числом

Технический контракт обсуждения: GET /api/kommentarii поддерживает
zadacha_id, sortirovka=id_asc или id_desc и do_id для получения более
ранних записей. Сначала показываются последние 50 реплик, предыдущие
подгружаются отдельным действием. POST создаёт реплику с HTTP 201,
PATCH возвращает HTTP 200. PATCH и DELETE требуют увиденную versija
upominanija передаёт точные ID и границы выбранных имён, проверяемые
сервером; время создания и изменения задаёт сервер

### Материалы и документы

Два разных блока, не один. Разделены потому, что ищут их по-разному:
материал ищут по теме, документ по номеру и дате

```
Материалы     рабочее: макеты, записи, статьи, презентации, ссылки
Документы     юридическое: договоры, акты, счета, НДА, доверенности
```

**Где есть оба блока**

```
человек          материалы и документы по нему
проект           материалы и документы проекта
направление      материалы и документы направления
задача           только материалы, документы к задаче не крепятся
```

**Что можно приложить**

И файл, и ссылку, в обоих блоках:

```
кнопка «добавить»  →  загрузить файл   или   вставить ссылку
```

```
файл     до 50 МБ
         хранится в Локусе, скачивается по нажатию

Файл больше 50 МБ не загружается: показывается отказ с текстом
«файл больше 50 МБ, приложите ссылкой». Исполняемые файлы
не принимаются: exe, app, sh, bat, cmd
ссылка   адрес плюс подпись
         открывается в новой вкладке, значок домена рядом
```

**Поля документа** отличаются от материала:

```
материал    название, файл или ссылка, кто добавил, когда
документ    название, тип, номер, дата, файл или ссылка,
            кто добавил, когда
```

Тип документа: договор, допник, акт, счёт, НДА, доверенность, другое

**Документы показываются сверху вниз по дате**, у каждого видно номер
Материалы по дате добавления, у каждого видно, кто добавил

**Один файл виден в нескольких местах.** Договор с Игорем по Synapt виден
и в документах человека, и в документах проекта, и в документах
направления. Файл при этом один, не три копии

**Почему теперь храним файлы, а не только ссылки.** Раньше в ТЗ стояло
«только ссылки, всё лежит в Google Диске». Решение изменено 22 октября:
ссылка на Диск умирает при смене прав или переносе папки, а договор нужен
через год. Документы храним у себя, материалы можно и ссылкой

### Вложения к задаче и комментарию

К задаче и комментарию прикрепляются материалы: файл или ссылка. Блока
документов там нет, документ живёт у человека, проекта или направления

## 5а. Журнал изменений

Записывает, что на что поменялось и кто поменял. Нужен не только для истории:
без него не работает автозамер ОКР по воронке. Нельзя посчитать «сколько лидов
стало клиентами в октябре», если не записано, когда они перешли

**В базе это одна таблица на все сущности**, иначе пришлось бы писать
пять одинаковых. Для человека это разные экраны, он таблицы не видит

```
что изменилось     человек, сотрудничество, проект, задача, цель
id записи
поле               статус, стадия, ответственный, срок, сумма
было               лид
стало              клиент
кто                редактор А, или Клод редактора А
когда              метка времени
```

**Что записываем:**

```
записываем                      не записываем
статус                          описание
стадия                          комментарий
ответственный                   заметку
срок и спринт                   иначе журнал утонет
суммы и платежи
привязка к цели
архивирование
```

**Где видно: секция «История событий» есть в КАЖДОЙ сущности**, а не только
общим списком в кабинете

```
карточка человека         что менялось по нему
карточка сотрудничества   стадии этого направления
карточка проекта          суммы, счета, кто ведёт, задачи
карточка задачи           срок, ответственный, статус, подзадачи
карточка цели             результаты, замеры, состояние
карточка рассылки         статусы контактов, правки текста
Полезное → Журнал         всё разом, с фильтрами
планёрка                  блок «Движения за неделю» строится отсюда
```

### Журнал в Полезном

Отдельная вкладка в Полезном, не в Личном кабинете: журнал касается всей
команды, а не только меня

**Фильтры**

```
кто сделал       панель людей команды, несколько разом
направление      чипами
по кому          выбрать человека из базы
по проекту       выбрать проект
по задаче        выбрать задачу
что менялось     статус, стадия, ответственный, срок, суммы, архив
период           стрелками по неделям, или выбрать даты
```

Без фильтров показывает всё за текущую неделю, свежее сверху

**Строка журнала**

```
15:42   редактор А   Игорь Соколов, Synapt   роль: лид → клиент
14:10   участница Б     клиент А, стратегия      срок: 24.10 → 28.10
```

Нажала на строку, открылась та сущность, которую меняли

В карточке секция свёрнута, показывает три последних события и ссылку
«вся история». Это то, зачем журнал вообще нужен: чтобы по любому клиенту
и проекту было видно, что с ним происходило

**Что даёт бесплатно:**

```
сколько дней человек стоял в каждой стадии
конверсия лид → клиент за период, это автозамер для ОКР
кто поменял срок задачи и когда
восстановление после ошибочной правки: видно прежнее значение
```

## 5б. Уведомления

### Два потока, не один

Главное деление: иначе важное тонет в шуме

```
ПРО МЕНЯ      требует моего действия или касается моей работы
              колокольчик со счётчиком, бот пишет

СОБЫТИЯ       просто происходящее вокруг моих задач
              вкладка без счётчика, бот молчит
```

**Поток «Про меня»:**

```
команда добавила задачу                     сразу
команда добавила подзадачу                  сразу
у моей задачи поменяли срок                 сразу
меня добавили участником                    сразу
назначили меня ведущим проекта              сразу
сегодня истекает срок моей задачи           утром в день срока
моя задача просрочена                       утром на следующий день
```

**Формулировка «команда добавила», не «вам поставили».** Второе звучит
как приказ сверху, а работа у нас горизонтальная. Тот же чип
стоит в Моём пространстве: «добавлено командой»

Если известно, кто именно, имя подставляется: «редактор А добавил задачу»

**Поток «События»:**

```
комментарий в моей задаче
закрыли подзадачу в моей задаче
изменили задачу, где я участник
```

**Что не порождает ничего:** смена статуса человека, правка описания,
создание задачи, где меня нет

**Уведомления про согласование нет.** Статус «на согласовании» означает
«вынесено на общее обсуждение», а не «висит на конкретном человеке»
Согласования идут в Telegram, Локус их не ведёт

**Как выглядит.** Колокольчик в шапке со счётчиком непрочитанных:

```
администратор добавила задачу
Отрисовать баннеры для запуска            ← кликабельно, ведёт в карточку
Automy AI, Запуск курса, 2 часа назад
```

Название задачи ссылкой на карточку обязательно в каждом уведомлении,
без кавычек

**Счётчик.** На колокольчике число непрочитанных, до 9 цифрой, дальше
«9+». Ноль непрочитанных значит счётчика нет совсем, не кружок с нулём

**Прочитанное и непрочитанное.** Непрочитанные сверху, с точкой слева
и обычным текстом. Прочитанные ниже, без точки, текст приглушённый
Кнопка «прочитать все» в шапке списка

Прочитанные лежат 30 дней, потом исчезают

**Два повода по времени, а не по действию.** «Сегодня истекает срок»
и «моя задача просрочена» никто не нажимает: их приносит утро
Считает их `POST /api/uvedomlenija/po_srokam`, его зовёт утренний
запуск раз в день

Ручка идемпотентна: второй вызов в тот же день ничего не добавляет
Иначе запуск, сорвавшийся на полпути, при повторе удвоил бы колокольчик. Она же чистит прочитанные старше 30 дней: уборка
живёт там, где и так ходят каждый день, отдельного ночного задания
для одной строки не нужно

**Бот в Telegram** пишет то же самое. Настройка в Личном кабинете:

```
присылать в Telegram        да / нет
что присылать               всё / только задачи на меня / только просрочки
тихие часы                  с 22 до 9, по умолчанию включено
```

Текст бота тот же, со ссылкой на карточку задачи

**Чип «добавлено командой»** в Моём пространстве показывает то же самое:
задачи, которые поставил не я. Отдельного блока не нужно, чип справляется

## 6. Деньги

**Глубокой финансовой модели в Локусе нет.** Расчёты прибыли, налогов
и кассовых разрывов ведутся отдельно и сюда не переносятся

В Локусе три числа:

```
стоимость проекта      сумма, на которую договорились
ждём                   сумма платежей, которые ещё не пришли
пришло                 сколько пришло, с датами
```

### Как закрывается проект

Кнопка «завершить проект» в карточке. Локус показывает, что осталось:

```
Завершить проект «Агент под тендеры»

открытых задач       3
платежей не пришло   1 на 120 000 ₽

  ( ) закрыть задачи как сделанные
  (•) оставить задачи открытыми, они отвяжутся от проекта
  ( ) перенести задачи в другой проект

          завершить            отмена
```

Закрыть проект можно всегда, открытые задачи не блокируют: бывает, что работа кончилась, а хвосты остались

**Что происходит после**

```
проект            статус «завершён», уходит из активных списков
задачи            по выбору выше
платежи           остаются, непришедшие видны в долгах
показатели        остаются, считаются в прошлых периодах
```

**Вернуть в работу** кнопкой «возобновить», статус снова «идёт»

**Разница с архивом.** Завершён это «мы сделали», архив это «неактуально»
Завершённые проекты считаются в выручке и в воронке, архивные нет

**Стоимость проекта.** Поле в карточке проекта, заполняется при создании или позже

**Платежи проекта.** В карточке проекта блок «Платежи», кнопка «добавить
платёж». Это не бухгалтерия и не выставление счёта в банке, а строка
«ждём столько-то к такой-то дате»

```
сумма            обязательно
когда ждём       обязательно, дата
назначение       необязательно: первый этап, за октябрь
```

У платежа два состояния, третьего нет:

```
ждём        дата указана, деньги не пришли
пришло      дата оплаты заполнена, сумма в факте
```

**Просрочка это признак состояния «ждём»**, не третье состояние: дата
ждём прошла, деньги не пришли. На экране такая строка оранжевая
с подписью «просрочен на 5 дней»

Долги это сумма просроченных платежей

**Отметить оплату.** У строки кнопка «пришло». Подставляется сумма и сегодня,
обе правятся

**Пришло меньше, чем ждали.** Вписала 60 000 вместо 120 000, Локус
спрашивает:

```
Пришло 60 000 ₽ из 120 000 ₽

  (•) остаток 60 000 ₽ ждём отдельной строкой
  ( ) это всё, остаток списать

          отметить            отмена
```

Выбрала первое, появляется второй платёж на 60 000 в состоянии ждём
Выбрала второе, платёж закрывается суммой 60 000, разница не хранится

```
Платежи проекта                          + добавить

первый этап      120 000 ₽   ждём 25.10          пришло
второй этап      120 000 ₽   ждём 20.11          пришло
аванс             60 000 ₽   пришло 12.10
```

**Путь внесения один:** добавить платёж, потом отметить «пришло»
Отдельной кнопки «записать оплату без платежа» нет: иначе появятся
оплаты, которых никто не ждал, и прогноз поступлений развалится

Деньги пришли внезапно, платежа не было: добавляешь платёж задним
числом и сразу отмечаешь пришло, два действия подряд

**Задача создаётся не автоматически.** Нужна задача про оплату, человек
берёт шаблон «получить оплату»: подставляется проект, сумма и срок
из платежа. Это решение человека, а не автоматика на каждый платёж

Три платежа это три строки, а не три задачи

### Добавление платежа и проверка результата, 17 ноября 2026

Суммы доступны при явно заданном `dostup = polnyj`. Отсутствующее,
пустое и неизвестное значение закрывает денежные действия и суммы,
согласно позднему К-1671. Существующие значения доступа сохраняются

Форма добавления требует положительную сумму и дату ожидания,
назначение необязательно. Строка платежа показывает точную сумму
с копейками. Большие числа и длинное назначение помещаются на телефоне

POST /api/proekty/{id}/platezhi принимает необязательный `zapros_kljuch`,
UUID одного намерения. Повтор ключа у того же автора и проекта возвращает
созданный платёж, другое тело или проект получает 409. Проверка после
потери ответа выполняется GET того же адреса с `zapros_kljuch` в запросе
и заново проверяет денежное право. Перезагрузка не отправляет платёж снова

После отрицательной проверки можно явно повторить прежний ключ и тело
либо отменить добавление POST того же адреса с `otmenit_dobavlenie: true`
и прежним ключом. Отмена резервирует ещё не использованный ключ,
блокирует поздний исходный запрос и сохраняет уже созданный платёж

UUID сохраняется в имени локального черновика до отправки. Повреждённое
тело допускает проверку и отмену, без повторной записи непроверенных
значений. Отказ хранилища останавливает отправку. Внутренняя квитанция
хранит автора, область, хеши и событие создания; исходного UUID и суммы
в ней нет. Событие отличает удалённую запись от новой с тем же номером


### Что из этого видно

| Где | Что показывается |
|---|---|
| Проект | стоимость, ждём, пришло, до какой даты ждём |
| Планёрка | пришло за неделю, ждём до конца месяца, план периода |
| ОКР | факт оплат за период, если цель по выручке |

Если платёж не завели, сумма остаётся только в стоимости проекта
и в прогноз поступлений не попадает. Честнее, чем выдумывать

Прогноз поступлений это сумма платежей в состоянии ждём за период

Суммарная выручка периода складывается из оплат и сравнивается с целью, которую
поставили на период. Это и есть вся арифметика

### Что Локус считает про деньги, а что нет

```
Локус считает      стоимость проекта, платежи, сколько пришло
                   по услуге, направлению, клиенту, периоду

Локус не считает   расходы, ФОТ, налоги, прибыль, кассовые разрывы
```

Это не вопрос приоритета: разные вещи. Локус отвечает «сколько пришло
и за что», финмодель «сколько осталось»

Зарплат и выплат команде в Локусе нет. Выплаты рефералам есть:
они привязаны к приведённым клиентам

**Деньги видят все, у кого роль доступа это полный доступ.** У роли

### Услуги живут в карточке направления

Услуги это не общий справочник, а часть направления. Поэтому они лежат
блоком в карточке направления, рядом с описанием и материалами,
и правятся там же

**Блок «Услуги» во вкладке Контекст**

```
название      AI-чекап, ведение соцсетей
описание      что входит, в двух-трёх строках
цена          базовая, от которой считаем. Необязательна
ssylka        на страницу услуги, КП или лендинг
porjadok      перетаскиванием
arhiv         убрана из выбора, в старых проектах остаётся
```

**Цена базовая, а не обязательная.** Она подставляется в новый проект
как предложение, и её там можно поменять. У проекта своя стоимость,
независимая от справочника

Цена может быть пустой: у разработки её нет, считается каждый раз

Нажала «добавить услугу», заполнила три поля, готово. Разработчик не нужен

**Как выглядит блок**

```
Услуги направления Synapt                            + добавить

AI-чекап                                             открыть
полдня разбора процессов, отчёт с планом внедрения

сопровождение                                        открыть
ведение внедрения, два созвона в месяц

агент                                                ссылки нет
разработка и запуск AI-агента под задачу

разработка                                           открыть
сайт, бот, интеграция, по спецификации
```

Ссылка открывает страницу услуги в новой вкладке. Ссылки может не быть,
тогда вместо неё прочерк

**Списки на старт**

```
Synapt            AI-чекап, агент, разработка, сопровождение
Automy AI         курс, запись курса, корпоративный формат
Наставничество    наставничество, форум-группа
Медиа             съёмка, ведение соцсетей, стратегия
```

Курс принадлежит Automy AI, не Synapt: это разные направления

### Услуга в проекте

**Поле у проекта**

```
usluga_id     выбор из услуг этого направления
usluga_svoja  текст, если нужной нет
```

Список открывается раскрывающимся. Показываются услуги только того
направления, к которому относится проект: в проекте Медиа не предлагается
AI-чекап

### Что происходит при правке услуги

**Переименование спрашивает, что делать со старыми проектами**

```
Переименовать AI-чекап в Чекап

Услуга стоит в 14 проектах, из них 9 закрытых

  ( ) поменять во всех проектах
  (•) поменять только в новых, в старых оставить AI-чекап

          переименовать            отмена
```

Выбрала «только в новых», старые проекты остаются со старым названием:
у них в поле записывается текст «AI-чекап», связь со справочником рвётся
Так прошлые отчёты не переписываются задним числом

Выбрала «во всех», название меняется везде, связь сохраняется

**То же при смене цены.** Цена в справочнике поменялась, у проектов
остаётся та, что была на момент создания. Спрашивает только если
в проектах цена ещё не задана своя

**Архив.** Удаления нет: удаление осиротило бы прошлые проекты. Есть архив

```
Убрать услугу «агент» в архив

Услуга стоит в 3 проектах. В них она останется,
в новых проектах предлагаться не будет

          убрать в архив           отмена
```

Архивные услуги видно в том же блоке под чертой, с пометкой «в архиве»
и кнопкой «вернуть»

**Замена на другую услугу.** Если услуга завелась по ошибке или дублирует
другую, её можно слить:

```
Заменить услугу «чекап» на «AI-чекап»

Услуга стоит в 3 проектах. В них встанет AI-чекап,
а «чекап» удалится совсем

          заменить                 отмена
```

Это единственный способ удалить услугу насовсем: только когда её не на чем
осиротить, потому что проекты переехали на другую

**Своё значение можно превратить в услугу.** В блоке отдельным списком
видно, что люди писали руками:

```
Своё значение, не в списке

консультация          написали 4 раза       завести услугу
аудит процессов       написали 2 раза       завести услугу
```

Нажала «завести услугу», открылась форма с подставленным названием
После сохранения все проекты с этим своим значением переезжают
на новую услугу, поле `usluga_svoja` у них очищается

**Своё значение.** Если услуги нет, человек пишет своё в поле
`usluga_svoja`. Такие значения собраны в том же блоке направления
отдельным списком с числом употреблений: написали трижды одно и то же,
значит пора завести услугу

**Цена услуги и стоимость проекта это разные числа.** Одна и та же услуга разным клиентам уходит за разные деньги. В карточке услуги
лежит базовая цена, необязательная: она подставляется в новый проект
как предложение. Дальше живёт стоимость проекта, независимая
от справочника

```
cena у услуги        базовая, предложение. Может быть пустой
stoimost у проекта   на что договорились с этим клиентом
```

Цена услуги меняется, стоимость прошлых проектов не трогается

### Сколько зарабатываем и на чём

Локус отвечает на этот вопрос по своим данным: по пришедшим платежам
в разрезе услуги, направления, клиента и периода

```
по услуге         сколько проектов, сумма оплат, средний чек
по направлению    сумма оплат за период
по клиенту        сумма за всё время сотрудничества
```

Считается по пришедшим платежам, а не по стоимости проектов: план и факт
разные числа

**Где видно**

```
Направление, вкладка Проекты    суммы по услугам этого направления
Человек, карточка               сумма за всё время
Полезное, сводка по деньгам     все направления и услуги за период
```

**Чего Локус не считает.** Расходы, ФОТ, налоги, прибыль. Это финмодель
Локус отвечает «сколько пришло и за что», финмодель «сколько осталось»

**Исторические данные.** Услуга у прошлых проектов пустая: в старой базе
этого поля не было. Заполняется по мере работы с проектом, разом не проставляется. Сводка по услугам за прошлые периоды будет неполной, и это
видно на экране: «у 14 проектов услуга не указана»

### Этапы оплаты

**Общая сумма и этапы**

```
proekty.stoimost        общая сумма за весь проект
platezhi.summa          сумма этапа
platezhi.naznachenie    «первый этап», «за октябрь»
platezhi.zhdem_do       дата, когда ждём оплату
platezhi.oplachen_at    дата, когда пришло, пусто пока не пришло
```

Три этапа это три платежа у одного проекта. Общая сумма стоит у проекта
и с суммой платежей не связана автоматически

**Расхождение видно**

```
стоимость проекта    300 000 ₽
заведено платежами   200 000 ₽
пришло               100 000 ₽
```

Если сумма платежей больше стоимости проекта, показывается пометка:
не ошибка, а повод проверить

**Договорились сегодня, платит в следующем месяце.** У платежа дата
«ждём до», она и определяет месяц. Договорились в октябре, ждём
в декабре, значит у платежа декабрьская дата. В октябрьских деньгах
он не появится

### Связка с финмоделью: отложена

**Решение 22 октября: сейчас не делаем.** Нумерации в финмодели нет,
привязывать не к чему. Ручное проставление номеров это костыль, который
забудут заполнять

**Что вместо.** У каждого проекта и так есть свой номер в Локусе
Когда в финмодели появится нумерация, она возьмёт наши номера, а не наоборот: Локус первичен по проектам, финмодель по деньгам

```
проект в Локусе     номер 48, адрес locus.oreshkin.me/proekty/48
в финмодели         ссылается на 48, если нужно
```

**Поля `vneshnij_id` в схеме нет.** Когда понадобится, добавится одним
полем без переделки: связь по номеру проще, чем по отдельному ключу

**Что Локус отдаёт уже сейчас.** Выгрузка по проектам за период:
название, клиент, направление, услуга, стоимость, платежи с датами
Формат CSV или JSON, кнопка в разделе денег

Этого хватает, чтобы свести цифры руками раз в месяц, пока автоматики
нет
