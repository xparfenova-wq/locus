# Локус

Внутренняя рабочая система команды. Этот код проходит восстановление и&nbsp;приёмку; наличие экрана или&nbsp;успешного теста не&nbsp;означает, что&nbsp;принят весь продукт

Приложение запускается на&nbsp;Node.js 22.13 или&nbsp;новее и&nbsp;использует встроенный SQLite. Внешних зависимостей для&nbsp;сервера и&nbsp;API-тестов нет

## Проверка

`npm test` создаёт отдельные временные базы и&nbsp;процессы на&nbsp;случайных локальных портах. Он&nbsp;проверяет вход, запрет подмены человека и&nbsp;повышения прав, настройки, согласованный снимок базы, сохранность входа и&nbsp;задачи после перезапуска, откат при&nbsp;сбое журнала и&nbsp;основной контракт API

Сквозной сценарий связывает одного человека с&nbsp;несколькими сотрудничествами, проектом, задачей, рассылкой, целью и&nbsp;измеримым результатом. Он&nbsp;проверяет замер, конфликт версий, запрет изменения закрытого периода и&nbsp;сохранение задач после удаления цели или&nbsp;результата

Тесты не&nbsp;используют рабочую базу. `LOCUS_TEST_AUTH=1` разрешает заголовок автора только в&nbsp;тестовом процессе; сочетание этого режима с&nbsp;`NODE_ENV=production` запрещено

## Устройство

- `server.js` принимает HTTP-запросы, проверяет сессию, маршрутизирует API и&nbsp;отдаёт страницы
- `api/obschij.js` выполняет общие операции с&nbsp;версиями записей и&nbsp;журналом
- `api/opisanija.js` задаёт проверки полей и&nbsp;правила сущностей
- `api/dostup.js` проверяет право менять доступы отдельно от&nbsp;видимости денег
- `api/ekrany*.js` собирает данные экранов
- `api/podruchki*.js` выполняет предметные действия
- `db/` содержит схему, генератор и&nbsp;миграции
- `public/` содержит страницы, общий интерфейс, стили и&nbsp;необходимые ресурсы

Согласованные требования находятся рядом с&nbsp;каталогом приложения: `ТЗ-ЛОКУС.md`, `КРИТЕРИИ-ПРИЁМКИ.md`, `СХЕМА-БАЗЫ.md`, `БРЕНД-БУК.md`. `db/sborka_shemy.py` собирает SQL из&nbsp;документа схемы и&nbsp;вызывает `db/sborka_pravil.py`. Последний отдельно собирает действующие индексы и&nbsp;триггеры из&nbsp;миграций, чтобы новая база получила их&nbsp;без повторного исполнения исторических изменений данных

## Данные и&nbsp;доступ

Рабочая база `db/locus.db`, её&nbsp;WAL-файлы, вложения `fajly/`, резервные копии, журналы, пароли и&nbsp;переменные окружения не&nbsp;входят в&nbsp;исходники и&nbsp;пакет ревью

Вход создаёт HttpOnly cookie. Номер человека в&nbsp;заголовке браузера не&nbsp;даёт доступа. Публичная проверка `/healthz` сообщает только о&nbsp;доступности приложения и&nbsp;соединения с&nbsp;базой

Идентификаторы двух владельцев, которым разрешено менять права, задаются серверной переменной `LOCUS_ADMIN_IDS`. Без неё назначение прав закрыто. Право видеть деньги само по&nbsp;себе не&nbsp;делает человека администратором

Служебный `LOCUS_SERVICE_KEY` используется только фоновыми заданиями с&nbsp;ограниченным перечнем действий. Он&nbsp;не&nbsp;открывает произвольное чтение людей, задач и&nbsp;денег

## Выкладка

Рабочие данные остаются на&nbsp;сервере. Схема меняется миграциями, перед ними создаётся согласованный снимок SQLite с&nbsp;записями из&nbsp;WAL. Перенос локальной базы поверх рабочей запрещён

Любая выкладка должна иметь идентификатор версии, проверку исходной версии перед заменой, резервную копию, проверку после запуска и&nbsp;понятный откат. Полный переход на&nbsp;такой единый процесс, атомарные выпуски и&nbsp;проверка всех миграций входят в&nbsp;незавершённую часть восстановления

Исторический файл миграции с&nbsp;персональными хешами входа не&nbsp;должен передаваться на&nbsp;ревью. В&nbsp;экспортируемом пакете он&nbsp;заменяется пояснением; учётные записи создаются отдельно от&nbsp;исходников

## Что&nbsp;ещё не&nbsp;принято

Полная матрица требований, все действия интерфейса, нажатия и&nbsp;читаемость на&nbsp;телефоне, поведение всех миграций, восстановление всего сервиса, импорт старого Локуса и&nbsp;заполнение актуальных ОКР. До&nbsp;проверки этих пунктов система не&nbsp;объявляется готовой для&nbsp;всей команды


## Сообщения об ошибках

Форма открывается из кнопки информации об экране. Черновик привязан к участнику и сохраняется при закрытии и перезагрузке. Последнее настоящее действие хранится до 30 минут. При неизвестном результате форма сначала проверяет квитанцию, повторная отправка выполняется только явно с тем же ключом

Ручные и автоматические отчёты пишутся в `db/operational/errors.jsonl`, квитанции доставки — в `db/operational/reports/`. Оба пути входят в полную резервную копию. Запись не открывает SQLite; проверенная сессия может отправить отчёт и прочитать свою квитанцию при отказе базы. Полный журнал доступен только владельцу с полным доступом через GET `/api/oshibki`. Прежние записи общего журнала остаются на месте

Для личной доставки владельцу служба читает `LOCUS_REPORT_BOT_TOKEN` и `LOCUS_REPORT_CHAT_ID` из приватного окружения. Эти значения не входят в исходники. Отказ Telegram не мешает записи на диск; неизвестная доставка не повторяется автоматически, чтобы избежать дублей. Ошибка записи оставляет текст в браузере. Восстановление приложения не запускает отправку накопленных сообщений
