# Period plans and one goal identity

The main OKR specification says that the goal and its metric are shared across calendar windows. Four anonymous copies of a goal do not preserve manual observations, history or source identity. New explicit subperiod targets therefore belong to the original result, keyed by result and exact period. Independent legacy goals are never joined by title. The legacy clone API remains for compatibility; the main planner no longer calls it. Criterion K-266 still needs reconciliation with its literal “child goals” endpoint wording and is not silently marked accepted

A root result retains its own plan and baseline. A stored subperiod plan is a movement target. Flow indicators provide their interval contribution. State metrics require a dated starting observation; only the explicit root baseline anchors the start of the root period. An absent observation is unknown, not zero. The API returns the absolute state and movement separately. Views with an explicit subperiod plan show movement against that plan and retain the absolute state/date in the caption. Upper and lower targets never update each other

Migration 145 adds two empty tables. No prior row or history is inferred or rewritten. Period targets use canonical decimal TEXT, an optimistic version and a unique modification identifier. A complete batch validates every result, target, permission and closed period before writing. Exact decimal rounding allocates units to earlier periods (500 / 3 → 167, 167, 166). Mismatch is informational

Every mutation has an actor-scoped UUID receipt with an HMAC of the exact body. Cancel-before-arrival prevents later application. A saved receipt can be checked without exposing data after source deletion or permission changes. Undo uses a separate durable receipt, validates the original incarnation and every modified row, and returns the whole batch or nothing. The generic field undo cannot apply a partial period-plan change. Goal/result deletion snapshots period targets, checks them in the deletion fingerprint and restores them together with facts and links

Client drafts isolate actor, tab, goal and period. Acknowledging a request cannot erase a newer draft. Storage refusal blocks a write and keeps typed input. A transport failure leaves a pending intent; checking only reads the receipt. Retry is explicit with the same UUID. Conflict is preserved across reload until the person compares actual values and chooses their version. Access revocation removes old displayed values. Test and preview accounts are isolated; no real business writes or notifications are used
