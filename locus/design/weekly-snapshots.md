# Saved weekly reports

A past weekly report reads its saved JSON by direction, ISO year and week. The main screen and comparison share that read path. An explicit cutoff date requests a separate reconstruction. A current week stays live; an unfixed past week clearly says that it is a reconstruction. GET never creates, recalculates or augments a saved report. Storage failure or corrupt JSON is an explicit retryable error, not an absent report or live fallback. An ambiguous snapshot lookup without a direction is rejected.

Snapshots include the report's payment detail, team resource records, dated account measurements and insights. These use the same server bundle as the live screen. A historical screen does not fetch fresh supplemental APIs. A legacy snapshot without these blocks or period views reports their absence and does not borrow current data. Every existing snapshot identity was checked read-only before adopting strict validation; all 25 records had consistent keys and JSON.

The source caption shows the actual save or recalculation time in Moscow and identifies read-only viewing. No Sunday time is invented for a manually saved report. Historical quick-write controls are unavailable; links still open original business cards. Weekly comparison labels both ISO years, shows each source, rejects stale responses and clears prior values while the next week is loading. Access revocation removes a previously open comparison containing financial values.

The shared response policy removes financial insight prose as well as numeric fields. A payment amount in a sentence must not evade money permissions. Goal-related insight text retains explicit goal/result context for current and historical privacy checks.

A goal that becomes private is removed from an older shared snapshot, and its former progress cannot survive in the aggregate percentage. The screen explains that the aggregate is hidden under current permissions. A synthetic reproduction returned 4 percent after hiding the contributing goal; the protected response now returns unknown instead.

The outgoing server projections for current recurring tasks, task links and open-child counters stop at the saved weekly boundary. Current privacy checks still run. A real legacy snapshot exposed 44 differences because those projections refreshed recurring states after the saved JSON was read. A regression fixture preserves a completed recurring state and zero children after a new child is added. The client also uses the saved date for a missing overdue display flag, rather than today's date.

The explicit manual recalculation workflow, durable operation receipts and its dedicated history UI remain a separate unfinished acceptance step. Existing legacy POST behavior is not presented as a completed new workflow. No historical JSON is migrated or automatically rewritten by this release.
