# Перенос справочников старого Локуса

Инструмент переносит только людей, компании, каналы, школы, контакты и аккаунты
Направления сопоставляются с существующими кодами нового Локуса. Новые роли,
стадии, сделки, проекты, платежи, счета, цели, задачи и история не создаются
Старые доступы, пароли и личные таблицы не читаются. Выбор активного состояния
требует отдельного подтверждения администратора по ТЗ

Источник открывается только для чтения. `ops/legacy-dictionaries.cjs` выбирает
фиксированные поля четырёх таблиц: crm_contact, base_person, out_blog, med_acc
Перед переносом снять согласованный актуальный снимок этих полей из старой базы,
сравнить количество строк и SHA256 после передачи. Права снимка 0600, каталога
0700. Полную старую базу с авторизацией для переноса справочников передавать
не требуется

Предпросмотр на отдельной копии актуальной новой базы:

```sh
LOCUS_BAZA=/private/target.db node db/migrate.js
node ops/legacy-dictionaries.cjs plan /private/legacy-dictionaries.db /private/target.db /private/new-plan.json
node ops/legacy-dictionaries.cjs apply /private/legacy-dictionaries.db /private/target.db /private/new-plan.json 61
```

Миграцию запускать с LOCUS_BAZA, указывающим на свою копию. Файл плана должен
отсутствовать. В нём есть контакты и исходные поля: хранить приватно. В stdout
попадают только счётчики и хеш плана. Если целевая база или разрешённые поля
источника изменились, старый план отклоняется без записи

Сопоставление людей не использует имя как единственный признак. Общие почтовые
ящики не идентифицируют человека; разные Telegram-профили не объединяются через
совпавший телефон или почту. Тёзки, противоречивые контакты и повторяющиеся имена
без подтверждающей связи остаются на разбор. Организации и контактные лица
различаются: контактное лицо не становится собственным лидом. Владелец аккаунта
сопоставляется только с единственным действующим зарегистрированным участником
команды по точному нормализованному имени. Неизвестный владелец или уровень
сбора требуют разбора. Аккаунт старого проекта не превращается в аккаунт
направления до подтверждения проекта

`import_svjazi` хранит исходный ключ, часть записи, целевой ID, хеш и исходные
поля справочника. Изменённый после переноса источник не перезаписывает новую
запись. Неизменённый повтор не создаёт дублей, контактов, строк журнала или новых соответствий. Обычный API эту таблицу не открывает. Не разобранный
контакт сохраняется текстом для уточнения в заметке новой записи; ложного адреса
связи из него не создаётся. Весь исходный словарный набор сохраняется
в приватном соответствии. Поле длиннее допустимого не обрезается молча в этом
наборе. Превью отдельно сообщает неподдающиеся нормализации значения

Для рабочего переноса использовать только штатную процедуру после выпуска
и проверки кода на копии:

```sh
python3 ops/import_legacy.py --source /private/legacy-dictionaries.db --actor 61
```

Она разрешена только для /var/www/locus-novyj и службы locus-novyj. Исходник
и каталог резервирования находятся вне приложения. Операция берёт общий lock,
делает полный комплект и пробный перенос, затем закрывает запись, останавливает
службу и сохраняет ещё один полный комплект. Повторный план должен точно
совпасть с проверенным. После переноса проверяются все прежние строки каждой
таблицы, разрешённые приросты, внешние ключи и целостность. Служба запускается
с закрытой записью; доступ открывается после проверки health. Ошибка до этого
момента возвращает прежнюю базу и проверяет все строки повторно. После открытия
записи автоматического возврата старой базы нет

Результаты, план и оба комплекта находятся в приватном
/var/backups/locus-novyj/imports. После успеха сделать полный бэкап с проверкой
восстановления и внешней копии, затем проверить настоящий вход, поиск, карточку
импортированной организации/человека и контакты на вебе и телефоне. Отправка
сообщений, приглашений и подключение закрытых сборщиков в эту процедуру не входят
