# Выпуск и восстановление

`python3 ops/deploy_local.py` экспортирует HEAD из локального Git и обновляет
только `/var/www/locus-novyj`, службу `locus-novyj`, порт 8791. Незакоммиченные
файлы в выпуск не входят. Команда не меняет nginx, окружение, старый Локус или
таймеры. Для VPN используется en0; другой интерфейс задаётся LOCUS_SSH_INTERFACE.

После открытия данных выпуск проверяет настоящий HTTPS на 443 и запасном 8443:
health 200, POST без входа с Origin своего адреса 401, чужой Origin 403.
Проверка не создаёт записи и не расходует попытки входа. Отдельный запуск:
`python3 ops/deploy_local.py --public-smoke-only`. Ошибка этой последней проверки
делает выпуск неуспешным; после открытия данных старая база автоматически
не возвращается.

Перед остановкой службы выполняются миграция и запуск на полной копии.
После остановки создаётся ещё один согласованный комплект. До проверки нового
процесса обращения к данным получают 503. При отказе код и база возвращаются
из комплекта до снятия запрета записи. После открытия записи автоматического
возврата старой базы нет: такой возврат теряет новые правки и требует отдельного
решения человека. Выпуски и результаты лежат в `/var/backups/locus-novyj/releases`.

Снимки раз в 10 минут сохраняют базу, последние 48 комплектов. Ночной полный
бэкап сохраняет код, базу и вложения, последние 14 комплектов. Каждый полный
комплект разворачивается в отдельную папку; проверяются хеши всех файлов,
целостность, ссылки, число строк каждой таблицы и настоящий HTTP-запуск.
Пустая таблица задач допустима и не считается повреждением.

Для проверки или восстановления в сторону:

```sh
python3 ops/locus_ops.py verify /path/to/backup
python3 ops/locus_ops.py restore /path/to/backup /new/empty-app-directory
```

Назначение должно отсутствовать. Записать комплект поверх работающей системы
эта команда не позволяет. Для аварийного переключения сначала остановить
службу, сохранить текущий повреждённый каталог для разбора, восстановить в новый,
проверить и явно переключить WorkingDirectory и ExecStart.

Обычный полный архив не содержит `/etc/locus-novyj.env`, ключи TLS и настройки
служб. Перед каждым выпуском `deploy_local.py` сохраняет их отдельным
зашифрованным комплектом на компьютере оператора и отправляет его в приватный
`gdrive:locus-bekapy/locus-novyj/recovery-config/`. Обратное скачивание и SHA256
обязательны: при ошибке выпуск останавливается до изменения приложения.

Комплект содержит только настройки нового Локуса: окружение, обе конфигурации
nginx с зависимостями TLS, сертификаты и ключи, параметры продления с ACME-учёткой,
службы и таймеры `locus-novyj`, секцию gdrive из конфигурации rclone. Настройки
других сайтов и облачных дисков не копируются. AES-256-GCM защищает содержимое
и целостность. Ключ находится отдельно на Mac в
`../.recovery-secrets/recovery-configuration.key`, права 0600. Он не передаётся
на сервер и в хранилище копий. Каталог можно задать через
`LOCUS_RECOVERY_DIRECTORY`; сохранять ключ отдельно от сервера обязательно.
Потеря этого ключа делает зашифрованные настройки невосстановимыми.

Для отдельного обновления после изменения окружения, служб или TLS:

```sh
node ops/recovery-config.cjs pack --key /private/recovery.key --output /private/new-configuration.enc
node ops/recovery-config.cjs offsite --key /private/recovery.key --input /private/new-configuration.enc
```

Для проверки и распаковки на компьютере оператора:

```sh
node ops/recovery-config.cjs verify --key /private/recovery.key --input /private/configuration.enc
node ops/recovery-config.cjs extract --key /private/recovery.key --input /private/configuration.enc --destination /private/new-configuration-directory
```

Каталог назначения должен отсутствовать. Команда проверяет все хеши и пути
до записи, отвергает выходящие наружу, циклические и отсутствующие ссылки,
сохраняет относительные ссылки сертификатов. Каталоги создаются с правами 0700,
файлы с 0600. Поверх `/etc` команда ничего не устанавливает. После проверки
перенести только необходимые настройки на новый сервер по SSH, не публиковать
распакованный комплект и не оставлять его во временных общих каталогах.
`root/.config/rclone/locus-gdrive.conf` содержит одну секцию: для восстановления
использовать `rclone --config /private/locus-gdrive.conf`, не заменять общий
конфиг дисков без проверки.

На чистом сервере нужны Node >=22.13, Python3, nginx, OpenSSL, certbot с nginx
и rclone. Восстановить приложение в новый каталог, проверить пути в службах,
установить окружение с 0600, затем `systemctl daemon-reload`. Список включённых
служб сохранён в зашифрованном комплекте; включать только их. Сначала проверить
приложение и HTTPS, затем запускать таймеры. Секреты не передаются в Git или
открытые архивы.

Конфигурации нового адреса сохранены в `ops/nginx-locus-novyj.conf` и
`ops/nginx-locus-novyj-zapas.conf`. При восстановлении сначала подготовить DNS
и сертификат для адреса, затем проверить пути TLS и установить эти файлы
в sites-available с соответствующими ссылками sites-enabled. До reload обязательно
`nginx -t`. В Host нужен `$http_host`, чтобы сохранялся и порт 8443. Переменные
nginx записываются без обратного слеша перед долларом; буквальный `$host`
в заголовке ломает защиту Origin и вход из браузера. Лимит 50m одинаков на обоих
адресах. Конфигурации других сайтов не заменять. После reload выполнить внешний
smoke выше и настоящий вход из браузера, включая проверку возврата на исходную
страницу.

14.11.2026 выполнено восстановление текущего полного комплекта в пустой
Linux-контейнер с Node 22.23.5, Python, nginx и OpenSSL, без сети и без доступа
на запись к исходному бэкапу. Проверены все 173 файла, целостность, внешние ключи,
число строк всех таблиц, 29 файлов настроек, `nginx -t` и определения 11 служб
через `systemd-analyze verify`. С восстановленным действующим сертификатом
проверены оба HTTPS-порта, Origin 401/403, вход с временным паролем только в
одноразовой копии базы, защищённая cookie и право правки чужого графика.
Две независимые правки сохранились, одна из двух правок одного поля получила
409. Повторная миграция сохранила точный хеш всей истории версий, авторов и дат;
после перезапуска сессия и отказ устаревшей правке сохранились.

Сценарий `ops/rehearse_restore.py` запускается только в одноразовом Docker
с `--network none` и `LOCUS_ISOLATED_RESTORE=1`. Нужны пустой каталог приложения,
монтирование полного комплекта в `/backup` только для чтения, предварительно
проверенные распакованные настройки в `/configuration` только для чтения,
свой каталог результата в `/output`. Он изменяет исключительно копию базы
и файловую систему контейнера. При переносе архива с Mac назначить файлам
настроек владельца root внутри своего временного каталога: исходный UID Mac
иначе недоступен контейнеру с ограниченными capabilities. Для nginx нужны
SETUID, SETGID, CHOWN; остальные capabilities отключены. Образ содержит
Node >=22.13, Python3, nginx, CA-сертификаты и systemd-analyze.

Контейнер не подтверждает загрузку новой машины под systemd, смену внешнего IP,
перенос DNS и выпуск/продление нового сертификата. Адрес nip.io привязан к IP;
при смене IP подготовить новый адрес и сертификат до переключения. Эти пункты
остаются отдельной приёмкой. Внешние интеграции и таймеры в репетиции не запускаются.

Отдельное право администратора править чужой график задаётся в окружении службы
`LOCUS_GRAFIK_ADMIN_IDS` — список ID через запятую. Пустое значение оставляет
только правку своего графика. Этот список независим от `LOCUS_ADMIN_IDS`:
полный доступ к деньгам сам по себе не даёт права менять чужие часы.
После восстановления окружения и запуска проверить `GET /api/poleznoe`:
`grafik_mozhno_pravit_chuzhoj` должен быть true у администратора и false у обычного
участника. Миграция 099 добавляет версии графика; старая копия интерфейса
без versija больше не может перезаписать изменённую строку.

Ночная копия отправляется в уже настроенный приватный
`gdrive:locus-bekapy/locus-novyj/`. Отправка подтверждается обратным скачиванием
и совпадением SHA256. Отказ виден в systemd и в поле внешней копии состояния.

Архивы содержат персональные данные и хеши паролей. Права каталогов 0700,
файлов 0600. Их нельзя публиковать или включать в пакет ревью. Локальная история
Git с прежними персональными хешами также остаётся приватной.

Применённые миграции получают SHA256; удаление, переименование, изменение
файла или повтор номера останавливает накат. Первое заполнение SHA256 фиксирует
текущий проверенный каталог, не доказывая его неизменность до перехода.
